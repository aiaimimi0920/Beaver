# Beaver

**通过对话制作 Godot 游戏的本地工作室。** 你安排目标、审阅素材、试玩游戏；Codex 自行决定如何使用 Godot、Blender 和 AI 服务。Beaver 不要求你编排 AI 的内部步骤。

**最新开发检查点（2026-10-01）**：当前原生 Tauri/Rust 开发版为 `0.1.19.43`。已接通最终候选逐区重新确认、独立冻结 PNG 来源及显式接受/发布门禁，并完成定向回归、原生构建、固定包校验和保留轮次的真实 WebView2 只读核对。**全部开发计划和整体验收尚未完成**；当前候选仍需用户保存最终 output 编号帧并自行决定是否接受、发布。状态及手测入口见 [手工测试说明](docs/MANUAL-TEST-READINESS.md)，剩余条件见 [框架计划](docs/FRAMEWORK-IMPLEMENTATION-PLAN.md)。

GitHub 仓库保存源码、测试、资源和文档，不包含本机 `release/`、`output/`、测试凭据或运行数据。文档中的本机证据与手测启动器链接仅在原开发环境可用，不是仓库内的下载入口。克隆后可用 `npm ci`、`npm run build:native` 构建原生开发版；Windows 需要 Rust/MSVC 和 WebView2，实际创作、预览还需配置可用的 Codex、模型服务及 Godot/Blender。构建成功不等于游戏创作或发布验收通过。

历史 R19 预览保留五官与颊颌、发根、阴影诊断、拓扑与法线检查等 NPR 人物制作提示词，并修复内容相同的文件被判为合入冲突的问题，提供无需重新运行 AI 的 `task.retryMerge` API。原角色的四个子任务及父任务已全部完成并验收，见 [R19 验收记录](docs/R19-ACCEPTANCE.md)和 [R16 角色精修记录](docs/R16-ACCEPTANCE.md)；该历史结果不代表当前完整计划已验收。

创作任务的拆分、审批、中断恢复及标准导出流程见 [R13 验收记录](docs/R13-ACCEPTANCE.md)和[任务执行契约](docs/TASK-EXECUTION-PLAN.md)。以下部分界面介绍保留旧 Electron 原型的历史说明；默认 Electron 构建入口尚未切换。

历史 Electron 原型：**0.1.10 Windows x64 交互原型预览版**。总览改为左上游戏名称、右上独立设定卡，左侧其余区域留白；二级设置使用带图标的卡牌选择弹窗，详见 [0.1.10 更新](docs/UPDATES-0.1.10.md)。保留默认编辑锁、保存后的强风险提示、78 项功能包规划和 Loom 紧凑壳层。**项目规划表单仅保存在本地；实际制作从创作任务开始。** 发布包不内置任何人的 API Key。

## 直接使用

当前本机固定的 Windows 原生开发包位于 `release/Beaver-native-0.1.19.43-win32-x64/Beaver.exe`，未随源码提交到 GitHub。先从托盘退出旧版，再按 [手工测试说明](docs/MANUAL-TEST-READINESS.md)打开新版；关闭主窗口只会隐藏到托盘。保留完整发布目录及许可证文件。开发包未签名；旧版发布目录未覆盖。

本轮白发草帽角色及 NPR 实验室交付位于 `release/Beaver-game-DlYQUM/Game.exe`。请保留整个目录，包括 `spoutlibrary.dll`。标准导出包已通过完整性校验、内容一致性检查及真实窗口交互验证；角色仍有简化，尚未达到银狼参考的完成度。

1. 启动 Beaver，打开“设置”的“本机工具”，会自动检测并填入可用路径。支持 Windows 注册安装、Steam 安装位置、快捷方式和系统记录的便携 Godot。没有检测到时可以安装或选择已有程序；Blender 是 3D 制作的可选工具。保存后固定所选路径，不会自动升级或切换你指定的引擎版本。
2. 选择 AI 来源：
   - **自配 API**：点击“从本机 Codex 补齐”可保存当前设置并补齐编程、审查、翻译的空白项；也可手动填写。图像、语音、音乐仍需对应媒体服务的 Base URL、模型与 Key。
   - **平台 AI 额度**：配置运营方提供的平台网关、令牌和各能力模型。客户端已经区分两种路由，但仓库不包含真实充值、支付、账户和计费后台。
3. 新建“夜航调饮室”或空白项目，也可以接管包含 `project.godot` 的已有项目。创建分为基本信息、创作方向、功能规划；主/副类别、主题、评级、规模和联机容量会保存为草案。**本版勾选功能规划不再提交接入任务**，模板只在创建时应用。
4. 在“总览”右上设定卡查看主副类别、主题、评级、大小与联机状态。先开启“编辑设定”，再点击对应齿轮进入二级选择；卡牌弹窗中的“应用”只更新草稿，“保存设定”才持久化并提示风险。左上名称只改变 Beaver 展示名，不重命名目录或游戏程序。“项目设置”继续调整三阶段 15 项优先级和发行草案。见[总览契约](docs/ui/PROJECT_OVERVIEW.md)与[项目规划契约](docs/ui/PROJECT_BLUEPRINT.md)。
5. “功能块”的“功能包规划”可选择 78 项能力或源码包，保存为项目目标；只有“源码包”页中的 10 个包有真实“接入 / 更新”动作。需要实际制作时，在任务工作台明确描述目标；新规划暂不自动加入 Codex 提示词。原任务和素材入口继续真实可用。
6. 在素材页选择参考图片、框选问题区域、试听音频、旋转查看模型，或截取游戏窗口，再交给任务。
7. 试玩并确认效果。导出游戏时选择已有 Godot 桌面导出预设和项目外的目录。导出需要与 Godot 版本匹配的 export templates；导出的玩家程序不需要 Codex 或 Godot 编辑器。

**关闭窗口不会停止任务**：应用留在托盘继续执行。托盘“退出程序”会停止本次受管理的执行进程，保存工作副本和会话；下次打开后点击“继续”。不会未经选择自动恢复耗费额度的任务。

### AI 接口约定

- Codex 编程、独立 review、翻译使用兼容 **Responses API** 的服务，不是任意 Chat Completions 接口。
- 图像默认 `/images/generations`；带参考图时默认转为 `/images/edits`。显式自定义路径保持不变。
- 语音默认 `/audio/speech`。
- 音乐没有伪造通用供应商协议：需要显式填写路径，服务接收 `model/prompt`，返回音频二进制或 `data[].b64_json / url`。异步供应商需通过适配网关接入。
- 未配置、鉴权失败和生成失败会真实报错，不回填假素材。[完整接口说明](docs/AI_SERVICES.md)。

## 边界与安全

- **任务副本不是系统安全沙箱。** 默认授权 Codex 自主使用本机工具；只能用于可信项目及你授权的任务。应用不改写个人 `.codex`、`.codex-gd` 或它们的认证文件。
- 标准回退覆盖任务管理的项目文件内容，不回退外部网络请求、账户费用、系统安装、项目外文件或操作系统元数据。
- 同一文件被其他任务或外部工具修改时不会强行覆盖。不同文件的逻辑依赖仍需 Codex 验证和人工试玩。
- 独立 review 服务可以只做审查，但这里不是强制隔离的安全审计沙箱；若其修改工作副本，系统拒绝自动合入。
- 默认本地数据保存在 Electron 的应用数据目录；日志、任务副本和快照会占用磁盘。当前不自动删除历史快照，避免破坏回退链。
- 3D 场景不是内嵌 Godot 编辑器。首版通过场景文件、对象名称和运行截图反馈；`.blend` 源文件交给 Codex 转换后预览。
- Windows x64 已验证；macOS/Linux 尚未进行真实打包、签名和系统验收，不能宣称已经支持完成。

## 开发与验证

原生主机提供可选的本地业务 API 与 `--business-mcp`：52 项业务操作复用桌面执行逻辑，支持能力发现、审批策略及显式路径导入。配置、调用示例和未完成项见[业务 API 文档](docs/BUSINESS-API.md)。R7 及更早发布包不包含此功能。

需要 Node.js 22.13+、npm。桌面应用运行时自带 Electron，不要求玩家安装 Node。

```powershell
npm ci
npm run check
npm run start
npm run package
```

若 Electron 二进制被环境安装策略跳过，运行 `node node_modules/electron/install.js` 后重试。打包不会覆盖已有同名 release；用 `BEAVER_RELEASE_DIR` 指定新的输出目录。

```powershell
npm run format:check
npm test
npm run verify:codex
# GODOT_PATH 指向真实引擎，且当前用户已有匹配的导出模板：
npm run verify:godot
# 新增逻辑模块的真实 Godot 编译与行为检查，不需要导出模板：
npm run verify:features
# BEAVER_PLAYWRIGHT 指向外部安装的 playwright 包目录：
npm run verify:desktop
```

`verify:codex` 使用**真实 Codex 进程 + 本机固定协议应答**测试会话，不调用真实模型、不使用个人 Key，不证明生成质量。`verify:desktop` 使用真实 Electron 和真实 IPC，不替换业务后端。运行证据写入 `output/validation/`。
