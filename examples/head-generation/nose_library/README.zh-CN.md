# 调研驱动鼻形库

本库将论文与 358 组游戏角色正侧观察转为自主构造，不包含第三方模型、纹理或截图资产。

## 组织方式

- `fused` 共享融合式简化鼻核心：`compact`、`balanced`、`elongated` 三个可连续调整的起点。
- `pad-muzzle`：独立闭合鼻垫与鼻周上吻部支撑。不是完整动物嘴、下颌或角色复原。
- `faceted-candidate`：真实平面三角构造的独立棱面模块。仅有单例研究方向，不声称覆盖机械角色。

三个通用起点不是三个互斥的自然形态族。合成角色身份本身也不是特殊鼻形的判据。

研究依据：[连续参数与离散部件](https://arxiv.org/abs/2209.02600)、[鼻形术语](https://doi.org/10.1002/ajmg.a.32600)、[鼻底局部分类](https://doi.org/10.1001/jamafacial.2017.1785)、[参考图来源](https://sites.google.com/view/referencearchive/archive)。鼻底分类不能替代整鼻，未见的鼻孔与底面不补猜。图像作者与游戏风格集中，不代表行业全面覆盖。

## 实际入口

`face_components/catalog.json` 新增以下鼻部选项，保留原四个旧选项：

- `research-compact`
- `research-balanced`
- `research-elongated`
- `research-pad-muzzle`
- `research-faceted`

`face_components/bundle.py --nose-controls controls.json` 及 `plan.py --nose-controls controls.json` 接收可选数值覆盖；没有研究预设时不接受覆盖。控制对象不能修改 `kind`、`version`、其他面部槽位或混入旧鼻模板。组合快照保留设计与源文件指纹。

`nose_design.py` 中的范围是作者设定的工程域，不是从参考图测量出的毫米或角度。核心参数分别控制鼻根高度、鼻尖高度、前突、半宽和圆钝。新鼻结构在归一高度 0.19 至指定鼻根之间作用；上吻部另用 0.17 至 0.36 的紧支撑场。嘴缝、嘴角、眼和耳仍须实测回归，参数不变不等于几何必然无影响。

## 几何与解析一致性

- 新通用鼻使用端点零切线的单峰纵向曲线和连续横向形状混合。
- CPU 分析、原生生成共享发出的函数；区间包络同步处理横向混合和上吻部紧支撑界。
- 旧鼻形的后处理不适用于新解析形状，不再叠加；报告明确记录这个阶段不做位移，不能据此声称旧的位移上限认证了新鼻形。
- 特殊附件是独立闭合网格，不做隐含布尔合并。附件首先按已求值的中性脸壳放置，鼻垫背面与边界嵌入支撑；棱面模块有暴露边缘和封闭侧壁，不冒称整个边界贴平。
- 原生守卫检查有向边配对、正体积、三角面积，并对附件背面顶点采样最终三角化脸壳，拒绝未贴合或过深的样本。它不是连续全局碰撞证明。
- 附件在旧部件顺序确定后加入，仅分配新的语义区域编号；旧眼、眉、耳及侧叶区域编号保持不变。保留冻结身体指纹和嘴部运动规则。

## 验证与状态

`native-evidence.json` 只记录完成的历史样本；`pending_presets` 表示尚未完成原生验收的预设。新输出仍必须重新生成、烘焙和检查，不以相同选择或旧截图跳过验证。

必要检查包括：
1. 原生生成、输入及输出指纹、组合快照、发出的设计与源代码绑定。验收 spec 必须提供启动前保存的 `composition_sha256`，不能只按预设名称匹配连续参数。
2. 同相机正面、45°、90°；普通渲染、白模和线框。
3. 眼部闭合、嘴部姿态及至少一个跨部件组合。
4. 冻结身体、耳连接、特殊附件实际支撑和拓扑。

当前脸部 SDF 的 `smooth_proxy` 与 `mesh_normals` 都只处理区域 1，不含独立鼻垫或棱面附件法线。SDF 成功不是特殊附件阴影、轮廓或最终审美通过。普通渲染与结构视图必须单独检查。

本库仍为头部开发功能，不等于完整人物、生产部署或最终审美验收。
