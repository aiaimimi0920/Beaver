# 六部位组合流程：第一条可执行路径

目标是六个独立造型库，不再用单脸版本数量衡量总体完成度。
本目录的直接使用者是 dot，通过命令行准备请求，再交给现有 Beaver 原生工具执行。
这里不启动 Blender/Godot，也不创建 Codex 任务。

## 当前范围

选择文件必须明确提供 eyes、brows、mouth、nose、ears、face 六个字段。
眼型使用现有8个工作家族；眉毛从眼型参数中分离，由独立眉型覆盖全部7个眉部参数。
睫毛和虹膜暂时随眼型走，尚未成为独立装饰库。

- 眼睛：8个现有家族，参考原 eye_presets 文档；新组合不继承原组合验收。
- 眉毛：soft-level 与 soft-arched 两个工程起始方案。前者复用810眉部设置，后者小幅增加弧度与外端抬升；不是已经完成论文/游戏调研的完整眉型分类。
- 嘴：保留型、已有上唇平滑过渡实验，以及 wide-neutral（较宽的中性嘴部开口与上唇横向支撑）。过渡实验不能算全新嘴型。
- 鼻：保留型和 defined-bridge（增强鼻梁肩部）；鼻尖、鼻根、鼻底参数保持不变。
- 耳：保留型和 compact-human（较收敛的外展跨度）；沿用原有耳根连接与接缝检查。
- 上述鼻、耳均为第一组有界实验，不能据此声称独立造型调研已穷尽。
- 脸型：保留型加4个局部宽度方案；这里只开放独立组合，仍需实际验证新搭配。

眉毛位置在眼部局部坐标系中跟随眼距与眼高，独立选择不意味着固定世界坐标。
所有选择在生成报告 face_components 中固化完整参数和摘要。切换眼型不会悄悄替换选中的眉型。
不覆盖795/796或其他已有模型目录。每个新组合必须使用新的 combo 前缀。

## 运行步骤

1. 复制 example-selection.json，选择部位 ID。
2. 用 bundle.py --selection SELECTION.json --prefix assets/aster/general_face_eyes_combo827/ --workspace WORKSPACE --output REQUEST.json 准备生成请求。
3. 通过 Beaver 的 blender.start 执行并轮询，保存成功回执。
4. 用 sdf_request.py --prefix PREFIX --workspace WORKSPACE --generation-receipt RECEIPT.json --output SDF.json 准备 SDF 请求，通过 Beaver 执行。
5. 在现有头部展示台打开 PREFIX/aster_definition.tres；检查正面、左右斜侧、白模、眨眼和张嘴，再登记实际结果。

SDF入口读取实际生成报告，不重新套用最新目录；报告必须与该次生成回执中的输出摘要一致，
并继续使用原有运行时 blend、GLB、参数与工作区回执校验。
成功 SDF 会修改报告；本入口目前不接受对已完成 SDF 的报告重烘焙，需保留首次请求以诊断，不能绕过绑定检查。

## 完成标准与后续

首阶段完成标准：六槽选择文件能真正驱动生成、SDF、预览，并保存可追溯组合参数和原生检查结果。
这与“六个造型库均完成”是两个里程碑。后者仍需每个部位的游戏/动漫/论文来源、形状定义、
提示词、参数、样例及跨组合适配规则；不能用类别数量乘积替代验证。

827已跑通最小路径（当时鼻、耳只有保留型）。后续新增鼻、耳、嘴变体须分别登记原生结果，不能继承827的验收。
下阶段扩展每部位的有来源造型目录与跨组合兼容证据，再扩展独立睫毛库。
仅在阻碍组合生成或造成明显缺陷时进行局部精修。


## 起始参考与证据边界

鼻与耳的起始参考来自《葬送的芙莉莲》官方人物图：
- [修塔尔克](https://frieren-anime.jp/character/chara_group1/1-6/)：正面鼻部较紧凑。
- [海塔](https://frieren-anime.jp/character/chara_group1/1-3/)：斜侧面鼻梁更突出，也可见人耳轮廓。
- [芙莉莲](https://frieren-anime.jp/character/chara_group1/1-1/)：长尖精灵耳为后续独立拓扑方向，目前未实现。

这些是视觉设计参考，不是从原图恢复尺寸。defined-bridge只是现有基底上的鼻梁肩部变化，
不等于已经复现海塔的长鼻；compact-human也只是人耳跨度变化，不等于精灵耳。
游戏样本扩充、部位级论文关联和更多类别仍待完成。论文将用于建模/变形方法和约束，
不能用“论文证明”替代观众对具体造型的美感判断。


## 组合提示词

[authoring-intents.zh-CN.json](authoring-intents.zh-CN.json) 为当前每个可选部位保存独立的造型意图。
选择器将六段所选文本与参数一起固化到生成报告，之后修改目录不会悄悄改写旧组合。
这些短文本是组合层的职责说明；不修改795/796和原眼型的定型提示词。
眼型描述只说明眼裂及当前随附睫毛，眉毛以独立眉型段为准，避免“保留原眉毛”与新眉型冲突。
文本本身不会触发外部模型调用；当前生成由已选择的显式参数确定，不声称已经支持任意自然语言捏脸。


## 组合适配与失败保留

829（杏仁眼+宽脸）的首次原生生成被侧睫毛4毫米修正限制拒绝，不能计为成功。
选择 `--fit-policy skin-seated-075` 可显式试验贴肤导轨：保留更多已经贴合自身皮肤的曲线，
只施加75%的端点曲线规整位移。它不是逐点截断，也不自动应用于全部脸型。
默认 legacy 保持既有构造；选项和完整数值会保存在组合快照中。

活跃策略仍保留初次4毫米检查，并在后续锚点/眼缘附加修正后增加最终合计4毫米检查。
原始目标位移、所选权重和最终位移均记录，根部/支撑/形变检查保留。
这只是新的几何构造，必须用新目录重新生成和检查，不能把参数可选视为组合已通过。

新增默认恒等参数后，SDF仍允许读取旧生成：报告与原生回执绑定的参数文件必须完全一致，
再用当前默认值归一化比较请求。默认1可与旧文件省略的字段一致，显式.75不能冒充旧生成。

### 跨部件原生验证（830 / 831）

见 [cross-combination-evidence.json](cross-combination-evidence.json)。830 使用细长眼、柔弧眉与宽下颌；831 使用杏仁眼、浅弧眉、宽嘴、增强鼻梁、收敛耳幅与宽脸。两组各完成 84 张眼部 / 混合表情截图和 18 张嘴部截图，校验源模型哈希、相机、显示模式与实际表情权重。已检查正面、斜面、闭眼、单眼闭合和张嘴渲染。

829 的旧贴合策略曾在杏仁眼与宽脸组合超过 4 mm 门限。831 显式采用 skin-seated-075，最大最终组合修正约 3.646 mm；门限未放宽。失败记录保留，不能把失败尝试计作已完成模型。

这些证据仅证明列出的组合跑通，不能推导全部排列组合均可用。眉、嘴、鼻、耳仍需要扩展有参考依据的造型类别，杏仁眼当前睫毛装饰也仍偏繁复。整体流程先行，审美精修继续独立记录。

## 统一计划入口

开始一个组合前，运行 `python plan.py --selection example-selection.json`。
可显式追加 `--fit-policy skin-seated-075`。输出 JSON 包括六部位快照、所选意图、已有证据、已知失败警告，以及生成 → SDF → 截图 → 人工视觉检查的顺序。此命令只读目录并输出计划，不启动原生程序，不改工作区。

证据严格区分“相同快照的历史记录”和“仅选择 ID 相同的旧记录”。例如当前重解 827、828、830 会因新增快照字段等变化得到不同摘要，仍保留其原始成果，但不能把它们算作当前快照已验收。即使 831 快照匹配，也没有证明当前全部生成器源码相同，因此新输出的步骤始终从 pending 开始。类别数量只是可选参数项数，不代表调研完成度或已验证组合数量。
