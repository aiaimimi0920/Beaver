# 六部位组合流程：第一条可执行路径

目标是六个独立造型库，不再用单脸版本数量衡量总体完成度。
本目录的直接使用者是 dot，通过命令行准备请求，再交给现有 Beaver 原生工具执行。
这里不启动 Blender/Godot，也不创建 Codex 任务。

## 当前范围

选择文件必须明确提供 eyes、brows、mouth、nose、ears、face 六个字段。
眼型使用现有8个工作家族；眉毛从眼型参数中分离，由独立眉型覆盖全部7个眉部参数。
睫毛和虹膜暂时随眼型走，尚未成为独立装饰库。

- 眼睛：8个现有家族，参考原 eye_presets 文档；新组合不继承原组合验收。
- 眉毛：soft-level 与 soft-arched 两个工程起始方案。前者复用810眉部设置，后者小幅增加弧度与外端抬升；不是已经完成论文/游戏调研的完整眉型分类。
- 嘴：保留型与已有上唇平滑过渡实验。后者只改唇面过渡，不能算全新的嘴型。
- 鼻、耳：当前只有 retained 明确保留选项。替代造型尚未实现，不能将一个空选择菜单称为分类库完成。
- 脸型：保留型加4个局部宽度方案；这里只开放独立组合，仍需实际验证新搭配。

眉毛位置在眼部局部坐标系中跟随眼距与眼高，独立选择不意味着固定世界坐标。
所有选择在生成报告 face_components 中固化完整参数和摘要。切换眼型不会悄悄替换选中的眉型。
不覆盖795/796或其他已有模型目录。每个新组合必须使用新的 combo 前缀。

## 运行步骤

1. 复制 example-selection.json，选择部位 ID。
2. 用 bundle.py --selection SELECTION.json --prefix assets/aster/general_face_eyes_combo827/ --workspace WORKSPACE --output REQUEST.json 准备生成请求。
3. 通过 Beaver 的 blender.start 执行并轮询，保存成功回执。
4. 用 sdf_request.py --prefix PREFIX --workspace WORKSPACE --generation-receipt RECEIPT.json --output SDF.json 准备 SDF 请求，通过 Beaver 执行。
5. 在现有头部展示台打开 PREFIX/aster_definition.tres；检查正面、左右斜侧、白模、眨眼和张嘴，再登记实际结果。

SDF入口读取实际生成报告，不重新套用最新目录；报告必须与该次生成回执中的输出摘要一致，
并继续使用原有运行时 blend、GLB、参数与工作区回执校验。
成功 SDF 会修改报告；本入口目前不接受对已完成 SDF 的报告重烘焙，需保留首次请求以诊断，不能绕过绑定检查。

## 完成标准与后续

首阶段完成标准：六槽选择文件能真正驱动生成、SDF、预览，并保存可追溯组合参数和原生检查结果。
这与“六个造型库均完成”是两个里程碑。后者仍需每个部位的游戏/动漫/论文来源、形状定义、
提示词、参数、样例及跨组合适配规则；不能用类别数量乘积替代验证。

下阶段优先补充鼻、耳和真正嘴型的独立变体，然后扩展眉型与睫毛库。
仅在阻碍组合生成或造成明显缺陷时进行局部精修。
