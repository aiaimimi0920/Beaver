# 六部位组合流程：第一条可执行路径

目标是六个独立造型库，不再用单脸版本数量衡量总体完成度。
本目录的直接使用者是 dot，通过命令行准备请求，再交给现有 Beaver 原生工具执行。
这里不启动 Blender/Godot，也不创建 Codex 任务。

## 当前范围

选择文件必须明确提供 eyes、brows、mouth、nose、ears、face 六个字段。
眼型使用现有8个工作家族；眉毛从眼型参数中分离，由独立眉型覆盖全部10个眉部参数。
睫毛和虹膜暂时随眼型走，尚未成为独立装饰库。

- 眼睛：8个现有家族，参考原 eye_presets 文档；新组合不继承原组合验收。
- 眉毛：soft-level / soft-arched 是柔顺收尖眉族内的两个设置；另有 angular-peaked 折锋眉与 broad-band 浓带眉实验。当前原生状态见 families.json 与对应候选证据，不把4个设置当作4个独立造型族。
- 嘴：保留型、已有上唇平滑过渡实验，以及 wide-neutral（较宽的中性嘴部开口与上唇横向支撑）。过渡实验不能算全新嘴型。
- 鼻：保留型、defined-bridge（仅增强肩部）及 long-bridge（显式延长上桥段并增加局部前突）。当前视觉分类仍归于一个紧凑楔鼻族，见下方834证据。
- 耳：保留型和 compact-human 属于人耳族；lateral-elf 为侧展尖耳族，837已有原生功能样例。保留共享耳根和接缝守卫，不能外推所有组合。
- 上述鼻、耳均为第一组有界实验，不能据此声称独立造型调研已穷尽。
- 脸型：保留型加4个局部宽度方案；这里只开放独立组合，仍需实际验证新搭配。

眉毛位置在眼部局部坐标系中跟随眼距与眼高，独立选择不意味着固定世界坐标。
所有选择在生成报告 face_components 中固化完整参数和摘要。切换眼型不会悄悄替换选中的眉型。
不覆盖795/796或其他已有模型目录。每个新组合必须使用新的 combo 前缀。

## 运行步骤

1. 复制 example-selection.json，选择部位 ID。
2. 用 bundle.py --selection SELECTION.json --prefix assets/aster/general_face_eyes_combo827/ --workspace WORKSPACE --output REQUEST.json 准备生成请求。
3. 通过 Beaver 的 blender.start 执行并轮询，保存成功回执。
4. 用 sdf_request.py --prefix PREFIX --workspace WORKSPACE --generation-receipt RECEIPT.json --output SDF.json 准备 SDF 请求，通过 Beaver 执行。
5. 在现有头部展示台打开 PREFIX/aster_definition.tres；检查正面、左右斜侧、白模、眨眼和张嘴，再登记实际结果。

SDF入口读取实际生成报告，不重新套用最新目录；报告必须与该次生成回执中的输出摘要一致，
并继续使用原有运行时 blend、GLB、参数与工作区回执校验。
成功 SDF 会修改报告；本入口目前不接受对已完成 SDF 的报告重烘焙，需保留首次请求以诊断，不能绕过绑定检查。

## 完成标准与后续

首阶段完成标准：六槽选择文件能真正驱动生成、SDF、预览，并保存可追溯组合参数和原生检查结果。
这与“六个造型库均完成”是两个里程碑。后者仍需每个部位的游戏/动漫/论文来源、形状定义、
提示词、参数、样例及跨组合适配规则；不能用类别数量乘积替代验证。

827已跑通最小路径（当时鼻、耳只有保留型）。后续新增鼻、耳、嘴变体须分别登记原生结果，不能继承827的验收。
下阶段扩展每部位的有来源造型目录与跨组合兼容证据，再扩展独立睫毛库。
仅在阻碍组合生成或造成明显缺陷时进行局部精修。


## 起始参考与证据边界

鼻与耳的起始参考来自《葬送的芙莉莲》官方人物图：
- [修塔尔克](https://frieren-anime.jp/character/chara_group1/1-6/)：正面鼻部较紧凑。
- [海塔](https://frieren-anime.jp/character/chara_group1/1-3/)：斜侧面鼻梁更突出，也可见人耳轮廓。
- [芙莉莲](https://frieren-anime.jp/character/chara_group1/1-1/)：侧展尖耳的方向参考；837已实现可辨识的侧展尖耳样例，独立后展角度与壳厚控制仍待补充。

这些是视觉设计参考，不是从原图恢复尺寸。defined-bridge只是现有基底上的鼻梁肩部变化，
不等于已经复现海塔的长鼻；compact-human也只是人耳跨度变化，不等于精灵耳。
游戏样本扩充、部位级论文关联和更多类别仍待完成。论文将用于建模/变形方法和约束，
不能用“论文证明”替代观众对具体造型的美感判断。


## 组合提示词

[authoring-intents.zh-CN.json](authoring-intents.zh-CN.json) 为当前每个可选部位保存独立的造型意图。
选择器将六段所选文本与参数一起固化到生成报告，之后修改目录不会悄悄改写旧组合。
这些短文本是组合层的职责说明；不修改795/796和原眼型的定型提示词。
眼型描述只说明眼裂及当前随附睫毛，眉毛以独立眉型段为准，避免“保留原眉毛”与新眉型冲突。
文本本身不会触发外部模型调用；当前生成由已选择的显式参数确定，不声称已经支持任意自然语言捏脸。


## 组合适配与失败保留

829（杏仁眼+宽脸）的首次原生生成被侧睫毛4毫米修正限制拒绝，不能计为成功。
选择 `--fit-policy skin-seated-075` 可显式试验贴肤导轨：保留更多已经贴合自身皮肤的曲线，
只施加75%的端点曲线规整位移。它不是逐点截断，也不自动应用于全部脸型。
默认 legacy 保持既有构造；选项和完整数值会保存在组合快照中。

活跃策略仍保留初次4毫米检查，并在后续锚点/眼缘附加修正后增加最终合计4毫米检查。
原始目标位移、所选权重和最终位移均记录，根部/支撑/形变检查保留。
这只是新的几何构造，必须用新目录重新生成和检查，不能把参数可选视为组合已通过。

新增默认恒等参数后，SDF仍允许读取旧生成：报告与原生回执绑定的参数文件必须完全一致，
再用当前默认值归一化比较请求。默认1可与旧文件省略的字段一致，显式.75不能冒充旧生成。

### 跨部件原生验证（830 / 831）

见 [cross-combination-evidence.json](cross-combination-evidence.json)。830 使用细长眼、柔弧眉与宽下颌；831 使用杏仁眼、浅弧眉、宽嘴、增强鼻梁、收敛耳幅与宽脸。两组各完成 84 张眼部 / 混合表情截图和 18 张嘴部截图，校验源模型哈希、相机、显示模式与实际表情权重。已检查正面、斜面、闭眼、单眼闭合和张嘴渲染。

829 的旧贴合策略曾在杏仁眼与宽脸组合超过 4 mm 门限。831 显式采用 skin-seated-075，最大最终组合修正约 3.646 mm；门限未放宽。失败记录保留，不能把失败尝试计作已完成模型。

这些证据仅证明列出的组合跑通，不能推导全部排列组合均可用。眉、嘴、鼻、耳仍需要扩展有参考依据的造型类别，杏仁眼当前睫毛装饰也仍偏繁复。整体流程先行，审美精修继续独立记录。

## 统一计划入口

开始一个组合前，运行 `python plan.py --selection example-selection.json`。
可显式追加 `--fit-policy skin-seated-075`。输出 JSON 包括六部位快照、所选意图、已有证据、已知失败警告，以及生成 → SDF → 截图 → 人工视觉检查的顺序。此命令只读目录并输出计划，不启动原生程序，不改工作区。

证据严格区分“相同快照的历史记录”和“仅选择 ID 相同的旧记录”。例如当前重解 827、828、830 会因新增快照字段等变化得到不同摘要，仍保留其原始成果，但不能把它们算作当前快照已验收。即使 831 快照匹配，也没有证明当前全部生成器源码相同，因此新输出的步骤始终从 pending 开始。类别数量只是可选参数项数，不代表调研完成度或已验证组合数量。

## 造型族与族内变体分别登记

[families.json](families.json) 将可选 ID 归入造型族，`plan.py` 输出对应清单。
每个可选 ID 必须且只能归属一个族；planned 族没有可执行选项。
当前脸型的4种宽度变化仍属于同一个保留轮廓族，嘴的宽度/过渡变化仍属于简线薄口族，鼻梁肩部和耳幅微调也不额外计算为新族。

眉部新增两个实验方向：angular-peaked（独立峰位与折转）和 broad-band（沿长度保留宽度、短圆帽收口）。原 soft-level/soft-arched 属于柔顺收尖眉。新方向的代码、原生验证和视觉验收需分别记录；加入目录不等于已完成审美验收。
角眉峰位使用既有24段采样近似，不声称连续曲线峰点被精确采样。新参数默认恒等，不改历史基底或原有定型提示词。

### 首组三类眉形样例

827柔顺眉、832折锋眉、833浓带眉已具有可辨识轮廓区别；后两者各完成原生生成、SDF、84眼部视图和18嘴部视图检查。见 [brow-family-evidence.json](brow-family-evidence.json)。它们共享下垂眼和窄下巴选择，本轮不把三类样例推广成全部眼型/脸型搭配已验证。

独立静态审查认为832的峰点和833持续保留的眉身宽度足以支持功能分类。833末端仍略收细，不称为完全平截端。白模的既有面部不平整仍保留为后续问题；本轮仅收束部件类型与完整工作流，不宣布最终审美交付。

## 鼻部独立长度与前突实验

`long-bridge` 在旧肩部尺度之外增加两个独立轴：`nose_bridge_length_scale`（1–1.2）将上侧站点围绕高度 .303 向鼻根延长；`nose_tip_projection_scale`（1–1.08）增加局部鼻尖站点前突。旧 `defined-bridge` 仍只改变肩部，不重命名旧结果。

这些是一次性构造输入，不承诺同一鼻部校准可任意重复叠加。保留站点宽度和鼻底标志点不等于保留完整插值表面；插值宽度、相邻斜率仍可能改变。现有鼻部细化与弧线平滑继续执行，3 mm细化与0.8 mm平滑限制保持不变，实际形状必须看最终侧面和正面。

834初步正面/45°/90°检查表明变化较克制，主要是鼻梁稍延长和鼻尖稍前突，整体仍保留原紧凑鼻型的轮廓组织。因此 `long-bridge` 暂作为紧凑楔鼻的族内实验变体登记，不计作第二个独立鼻型族；独立长鼻梁族仍为 planned。保留有用的构造控制，继续推进其他部位，不通过重复命名增加完成数量。

834完整原生生成、SDF与102张状态校验记录见 [nose-variant-evidence.json](nose-variant-evidence.json)。相对827，最终鼻尖深度增加约1.934 mm，弧线平滑最大位移0.435 mm，仍在原0.8 mm限制内。

## 批量证据复核

`coverage.py --batch <运行清单.json>` 只读复核明确列出的组合，不启动 Beaver。
清单是 JSON 数组，每行包含 `workspace`、`prefix`、六槽 `selection`、显式
`fit_policy`、`generation_receipt`、`sdf_receipt`、`eye_manifest`、`mouth_manifest`。
路径相对调用目录或使用绝对路径。必须使用原生 Beaver 回执；这是调用者提供的
可信记录，不是签名证明。当前仅支持回执所指的同一工作区。

复核包括生成阶段未被替代的全部输出、SDF 最终输出、SDF 输入清单与原生成报告
的哈希关系、不可变几何与参数、组合快照、着色策略，以及两组截图的图像哈希和
实际相机/表情状态。历史快照只补已知的恒等默认参数，不重新套用当前目录。
报告区分 `generation_failed`、`sdf_failed`、`incomplete`、`integrity_failed` 和
`technically_verified`；损坏的一行不会阻止其他行复核。

技术复核通过不表示美学验收或当前生成器可重现。`observed_pairs` 仅列已验证完整
组合中实际出现的部件对，不能外推其他组合；未提供证据的组合仍为未测试。

## 嘴部体积控制

新增 lower_lip_relief_scale（1–1.25）及 upper_lip_bow_height（0–0.003），
保持默认恒等；既有 upper_lip_relief_scale 区间不变。
分析和原生源共同使用上唇双肩 ridge，连续深度界限合入原4.2毫米预算。
口腔深度会跟随中性表面，必须复核张嘴状态，不能宣称口腔几何完全不变。
838的首轮图像显示下唇体积变化，但上唇弓在常规NPR渲染中不够鲜明，
因此实验预设仍归入简线口型族，不计作独立第二嘴型。

## 下巴曲率轴

`narrow-soft-chin` 与 `narrow-chin` 保持相同宽度设置，额外使用
`chin_softness=1`，将既有 `chin_return_lift` 从0.008降至0.004。
它改变底边横向抬升，保留默认0的原路径；不作为已证明的新脸型族。
直接竖直变化界限为0.944毫米，只覆盖平滑前、y≥1.544且|q|≤1的构造项。
重采样深度和后续下颌平滑仍会影响最终三维位置，不能将此数值当作全网格界限。
嘴眼承托存在指数衰减的非零影响，仍需完整原生组合检查。

## 版本化造型模板

流程顺序为保留基底 → 所选模板 → 兼容残差 → 原生构造与守卫。组合快照保存完整模板、版本和内容哈希；未选模板时保持原路径。当前只完成脸型模板的接口试点，嘴、鼻等独立构造模板仍待开发。

可选入口 `root-protected-round-chin` 使用 `root-protected-round-chin-v1`：
- 构造参数中保留归一高度 h≥0.16 的完整宽度三次曲线及切线，仅调整下巴底部，半宽变化界限5.9毫米。该声明不意味着后续平滑后的全部顶点绝对不变。
- 不允许非零残差；原2毫米局部残差与4.2毫米承托修正预算均不提高。模板构造变化与修正预算分别记录。
- 不回填旧模型坐标，不跳过耳根翻边、方向、接缝、口腔和表情检查。
- 先归入当前轮廓族的构造变体，不增加已实现脸型族数量。

实验注册表 `family-templates.json` 另保留以下历史定义，不从可选目录暴露：
- `soft-oval-width-v1`：较饱满下脸，h≥0.45完整曲线保持；841技术运行通过但双侧耳下有缺口，外观拒绝。
- `soft-oval-width-v2`：按最终宽度与保留宽度的差值，统一平移下缘支撑平面、后侧开口目标及正面耳下宽度目标。保留3/4毫米修正上限；843/844在耳根翻边优化检查失败，未绕过。

以上尺寸为作者设计，不是从参考图恢复的三维测量。诊断中的提议位移已内部限幅，不能当作原始未截断需求。失败及通过样本分别记录在 `template-pilot-evidence.json`，技术验证不等于新造型族或最终美学验收。
