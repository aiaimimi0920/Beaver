# 本地实现架构与数据保护

## 组成

```text
React / TypeScript 桌面工作台
  -> sandboxed preload / 白名单入口与逐方法 Zod 校验
  -> Electron 主进程
     - 项目、素材、系统目录选择与窗口截图
     - SQLite 任务/事件/配置/恢复日志
     - 按项目串行的文件合入锁
     - 每任务独立工作副本 + 内容寻址快照
     - LocalExecutor -> Codex app-server (stdio JSONL)
                         -> Godot / Blender / 自带媒体 MCP
     - Godot 试玩与桌面成品导出
```

技术栈采用 Electron + React + TypeScript、Node SQLite 和 Three.js。没有为了外观添加 HTTP 开发后端，也不在 renderer 暴露 Node。生产默认不开放本地网络调试端口。`TaskExecutor.location` 区分 local/cloud，云执行尚无实现，不会静默上传整个项目。

## 数据目录

以 Electron `app.getPath("userData")` 为根（Windows 通常在 `%APPDATA%` 下的应用目录）：

| 相对路径 | 内容 |
| --- | --- |
| `beaver.sqlite` 及 WAL | 项目、完整任务、事件、设置、加密凭据、功能块采用基线、文件操作日志 |
| `blobs/<sha256>` | 任务快照文件内容，按摘要去重 |
| `workspaces/<taskId>` | 每任务独立的可写 Godot 项目副本 |
| `codex/<taskId>` | 每任务独立 CODEX_HOME、会话、skills、MCP 配置 |
| `tools/` | 通过应用安装的独立 Codex 包 |

`BEAVER_DATA_DIR` 可指定**新的**数据根，用于测试或明确的部署选择，不是迁移工具。不要在任务运行时搬动数据目录。备份应先托盘退出，再同时备份应用数据和原项目；单独备份 SQLite 不能恢复 blob 或工作副本。

## 任务生命周期

### 0.1.7 项目规划与执行分离

项目记录新增可选 `blueprint` 与 `blueprintRevision`，不新增数据库表，不改写旧项目文件。`project.blueprint.save` 经过 Zod 校验，在单实例主进程的同步路径检查预期 revision 后保存；过期草稿拒绝覆盖。重新接管在文件读取完成后获取最新记录，保留读取期间刚保存的规划。

规划 UI 的阶段预览、发行草案和功能规划不调用执行器。新建会复制初始模板，但不按勾选功能创建任务。0.1.16 起，新建任务会冻结已保存的完整规划作为执行上下文；保存草案本身仍不执行业务、不影响已有任务目标，也不包含游戏文件标准回退。详细交互与备份边界见[规划契约](ui/PROJECT_BLUEPRINT.md)。

### 真实任务链

0.1.9 增加 `project.overview.save`：显式 `allowRiskyChanges: true`、严格字段校验和同一 `blueprintRevision` 并发检查，单次更新名称及基础规划；保留阶段优先级、功能选择和发行草案。旧 `project.blueprint.save` 拒绝改变基础字段，初次创建独立初始化。编辑开关是防误操作交互，不是权限或恶意 renderer 安全边界。总览与其他规划草稿独立保留，任一保存会让旧 revision 草稿过期，需确认重新载入，不能静默覆盖。名称仅更新 Beaver 元数据，不改文件路径、Godot 名称或旧 GameBrief。详见[总览契约](ui/PROJECT_OVERVIEW.md)。

1. 校验项目，在项目锁内读取文件内容并记录 baseline，然后复制到任务工作区。
2. 持久化任务为 queued；调度到 configured maxParallel（1–6）以内。
3. 为每个任务准备独立 CODEX_HOME。个人 Codex 配置、认证、MCP 开关和历史不被读取后覆写，也不自动复制。设置页仅在用户显式操作时导入 API 地址、模型与静态 Key，不导入完整配置。
4. 从任务副本的 `beaver.project.json` 读取并校验旧创作方向；若项目已有完整 blueprint，则以任务创建时校验并冻结的 `projectContext` 为准，将名称、规划 revision、类别、主题、评级、规模、风格、联网架构、阶段优先级及功能/发行意向送入真实 app-server turn。相同上下文写入 `.beaver-context/project/blueprint.json` 与 `brief.md`，并在会话「要求」中分页展示。旧任务保留原 GameBrief，不在恢复时悄悄切换规划。没有旧设计文件的项目仍可使用。默认无人值守授权；不支持的额外交互请求被拒绝并报告，不伪造人类批准。
5. 流式事件持久化；补充要求先保存，再通过 `turn/steer` 发送。若无法确认接受，记录说明，避免用户意图丢失。
6. turn 完成后重新快照工作区。只有非 review 修改、没有文件冲突且没有退出请求时，才合入原项目。
7. UI 显示交付与差异；用户另行认可。中止/失败不把部分工作强行合入，可原 thread 续跑。

关闭主窗口只隐藏窗口。托盘退出并行停止任务/游戏/安装检测子进程，等待持久化和正在处理的 IPC 请求结束后关闭 SQLite。重启先恢复文件日志，再把中断执行标记为可继续；不自动消费额度。

## 并发与合入

- 不同任务拥有独立项目副本，不共享 AI 工作目录。
- 合入仅涉及 baseline 与任务结果之间变化的文件。
- 原项目当前文件必须仍与该任务 baseline 相同；存在差异时整个标准操作拒绝覆盖。
- 同项目写入串行，不同项目可并行。导出占用项目锁，避免读取 Beaver 自己正在合入的一半文件。
- 这不是跨文件语义合并。脚本、场景和素材引用之间的逻辑关系由 Codex 验证及用户试玩确认。
- 项目规划按创建时冻结；后续创作和子任务是新任务，读取届时已保存的项目规划，同时继承原任务的参考及执行限制。已有任务不会因规划编辑而改写其执行上下文。规划中的服务器人数和功能选择不是已有实现、部署容量或批量执行授权。
- 用户在外部编辑器同时改文件时存在检查到写入之间的操作系统竞争窗口。请勿在合入/回退时从外部程序修改同一文件；本实现不是内核级文件事务或强制沙箱。

## 崩溃恢复与回退

文件操作先写 durable intent（每文件 before/after 内容摘要、任务结束态），然后进行临时文件写入和重命名，最后用 SQLite 事务同时提交任务状态与日志完成态。

重启发现未完成日志时，逐文件比较：

- 仍为 before：尚未写入，可以继续。
- 已为 after：该文件已经写入，不重复改写。
- 为第三种内容：视为外部修改，撤销能确认的本次写入，保留外部内容，标记冲突。
- 路径/权限不可用：保留日志和数据，阻止该项目继续安排写入，其他项目仍可打开；恢复原路径和权限后重启重试。

标准回退使用反向变更并同样记录日志。指定保留的文件不参与反向写入；后续任务改过的文件触发冲突，不用旧快照整项目覆盖。对话回退创建新的独立任务，提供原任务 before/after 文件与变更清单，因此它本身也有自己的回退边界。

保证范围是管理内的**文件内容**。忽略 `.git`、`.godot`、`.beaver`、`.beaver-context`、依赖、`release`、`exports` 等目录；符号链接/目录联接拒绝进入快照。空目录、文件权限、外部账户费用、系统安装和项目外副作用不在标准回退保证内。不能把程序崩溃恢复测试误写成断电/磁盘故障容灾证明。

## 功能块基线

0.1.8 的 68 项引擎能力使用独立 `EnginePackage` 元数据，`kind: planning`，不占用真实 `Feature` 清单或 `resources/features`。规划选择器合并元数据与实际源码包的展示信息，但不混合执行能力。`engine-` 命名空间在 `Tasks.feature` 读取资源前明确拒绝接入。创建、项目设置和功能包工作区共用 blueprint 草稿与保存操作，不建立第二套任务或安装状态。

接入任务的 `.beaver-context/feature/` 同时保存旧官方源、新官方源和 `upstream-changes.json`。当前项目副本保留定制。AI 适配完成且用户认可后才提交采用版本。

认可会比较创建任务时的采用基线，拒绝让过期任务倒退另一任务已采用的新版本。完整回退恢复前一个采用基线；保留部分文件的回退不再声称该版本完整采用。资源包目前随应用更新，没有假装存在在线集市。

## 安全边界

- renderer：contextIsolation、sandbox、禁止 Node、CSP、拒绝导航/新窗口/默认权限请求，IPC 校验发送方与主 frame。
- 素材协议：只解析注册项目或 `task-<任务 ID>` 对应的任务副本及合法相对路径，拒绝 `..`、盘符、ADS 和符号链接。不会作为任意路径读取接口。
- API Key：Electron safeStorage 加密；Linux basic_text 或不可用安全存储拒绝明文降级。日志和报告按已知 Key 脱敏。
- Codex：独立配置和服务 env；不把 API Key 明文写入生成的 config.toml。自主执行的 Codex 仍具备用户授权的系统能力，**副本隔离不等于恶意代码沙箱**。
- 媒体：明确供应商协议、输出路径预检、不可覆盖现存文件、参考数量/大小与响应体大小限制。
- 验证仅终止自己派生的进程树，不按进程名批量清理用户的 Codex/Godot/Blender。
