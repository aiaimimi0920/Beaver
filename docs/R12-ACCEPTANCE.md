# Beaver 改进与 R12 全新工程验收

2026-09-09。本次已完成已确认问题的修复，并用新 EXE、全新空工程跑通了输入、选项澄清、回答、创作、合入、认可、标准导出、包校验和首次试玩流程。

本轮验收关注制作交互与流程完整性。游戏平衡、趣味性和最终商业交付质量没有作为通过条件。

## 已完成的改进

1. 标准导出先导入同一份冻结工程，再执行导出。Godot 能力检测支持带 ANSI 颜色的帮助文本；不支持 `--import` 的旧引擎会得到明确的设置提示。导入和导出日志保留，非零退出码及引擎错误不会被当成成功。
2. 首次试玩同样执行资源导入。R11 的正式工程没有 `.godot` 字体缓存，启动后出现灰屏；新增的试玩导入修复了这一边界，并在 Beaver 数据目录保留独立的 `play-import-*.log`。
3. 任务状态、用户认可与导出校验分别表达。任务完成显示“已合入”，认可状态另行显示；项目保存最近一次导出快照的校验结果。包完整性通过不会将 `runtimeVerified` 改为 true。
4. 对改动过的已识别文本源码，在合入前规范为 UTF-8 无 BOM。资源读取严格处理 UTF-8、带 BOM 的 UTF-16；无法识别的编码保留原始字节，不以替换字符覆盖。新增 `task.resourceBytes` 和界面“下载原始文件”按钮。
5. 执行中的对话每 1.5 秒刷新事件，避免并发重复读取。符合白名单的终结型瞬时连接错误最多在原线程恢复一次，保留原有时限并记录恢复事件；认证、权限、配额、上下文和结果不明确的启动错误不盲目重放。
6. 新版测试启动脚本在编译前关闭旧 Beaver，分配独立数据与 WebView 目录，确认空状态，再通过业务 API 创建空白 Godot 工程。旧实例所属的试玩进程也随宿主退出。

接口发现实测返回 46 个业务操作。接口契约见 [BUSINESS-API.md](BUSINESS-API.md)。

## 保留的问题记录与验收边界

R11 曾遇到外部供应商 403、旧 Godot 4.0.2 导入行为、目录名与实际引擎版本不符、旧模板校验地址 404、外部模板相对路径，以及首次试玩缺少字体缓存。前几项通过合法配置和 Beaver 追补任务恢复，导入与试玩边界在程序中修复。完整过程保留在 [R11-IMPROVEMENTS-ACCEPTANCE.md](R11-IMPROVEMENTS-ACCEPTANCE.md)。

当前 `tools.install` 的行为是确保工具已安装，不能把它当成强制升级入口；标准导入要求所选引擎支持 `--import`。认证错误需要可用的供应商配置，不能作为网络重试绕过。本轮没有再被这些环境条件阻断。

这次证明了制作交互和主要流程可以跑通，并修复了测试中发现的实际阻断。发布包仍属于原生预览版；安装迁移、所有接口在两种传输上的逐项覆盖、标准导出 EXE 的完整独立运行验收和游戏品质评测，均不因本轮通过而被宣称完成。发布清单中的相关未验证标记保持原值。
