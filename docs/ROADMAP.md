# 后续目标

## 人类与 AI 共用业务能力

所有新增业务能力同时考虑桌面交互和程序调用，共用业务实现、状态与冲突保护。原生主机首轮已提供 44 项操作的本地 HTTP API 和 stdio MCP，详见[接入契约](BUSINESS-API.md)。仍需逐项补齐真实业务验收、调用来源记录、按项目/能力授权、持久化请求去重、长操作查询与事件订阅，以及面向人类的集成设置界面；当前本地令牌具有完整主机业务权限。

## 下一步：真实创作验收

- 用户配置真实 Codex 与媒体服务，完成原创对话调饮游戏的多轮制作和素材审阅，以用户认为满意为质量标准。
- 补充真实供应商超时、限流、费用、断网重试和图片/音乐编辑的端到端证据。
- 补齐平台 AI 账户、购买额度和结算后台。两种 AI 服务来源是已确认需求；后台尚未交付是当前缺口，不应理解成用户同意删掉此项。
- 用复杂已有项目验证跨场景引用、GDNative/GDExtension、自定义资源与多任务逻辑冲突。
- 完成干净 Windows 环境的安装器、签名、升级/卸载、自动安装工具验证和更友好的导出模板获取。
- 任务副本与 blob 的磁盘用量管理、可验证备份、显式历史清理、较大素材库索引和缩略图缓存。
- 功能块包的版本获取、包校验、依赖和供应商 changelog 展示；仍由 Codex 合并项目定制。

## 跨平台

- macOS 打包/签名/notarization、系统凭据、托盘与窗口截图权限、Godot 工具检测。
- Linux 包、桌面托盘差异、secret service、Wayland 截图和进程组清理验证。
- 玩家导出覆盖目标桌面系统；其他平台按真实 Godot 模板与渠道约束逐一验收，不宣称一次导出适配一切。

## 未来产品目标（明确延期）

1. 高级会员云执行节点；沿 `TaskExecutor` 边界实现，明确上传范围、断点恢复和产物同步。
2. 自有 itch 类游戏与素材集市：素材、模板、功能块和游戏交易、作者奖励、分成、审核。
3. itch、Steam、Epic 等渠道打包、发行和更新；微信小游戏需要独立渠道适配与真实验证。

更深入的场景/对象选择、游戏内反馈和素材审阅体验仍可继续增强；不把 Codex 的内部任务图变成人类必须操作的工作台。

这些是路线图，不是已实现清单。支付、集市、云执行、渠道发行不会以无效按钮或模拟余额出现在首版本地交付中。
