# Beaver 0.1.16 - 项目规划接入真实任务执行

## 本轮落地

这一版补上了项目设置到实际 Codex 执行之间的缺口，而不只是继续调整界面。

此前完整项目规划主要用于界面保存；任务执行仍使用旧版 GameBrief，目标评级、联机规模和阶段优先级等信息没有完整进入执行上下文。现在新任务直接使用已保存的完整规划。

### 项目约定成为任务上下文

新建任务在项目锁内读取并校验当前已保存规划，冻结以下信息：

- 游戏名称、主副类别、自定义或目录主题。
- 目标评级及素材表达边界。
- 游戏大小、表现风格。
- 在线多人开关；开启时包含拓扑、每房间人数、目标峰值、初期实例数和区域。
- 设计、开发、后期共十五项投入优先级。
- 规划功能包和宣传、试玩、媒体联系草案。

这些约定进入真实 Codex `turn/start` 请求，且与任务目标、参考文件和停止条件一起发送。完整规划存在时，不再同时发送可能互相矛盾的旧版规模与风格说明。

### 可追溯，不静默改变运行中的任务

- 每个任务持久化其规划版本和内容。
- 任务工作副本保存 `.beaver-context/project/blueprint.json` 和可阅读的 `brief.md`。
- 任务内「要求」显示相同的冻结约定，仍然分页显示，不增加解释型面板或滚动条。
- 后续修改项目设置，不会悄悄修改已存在任务的上下文。
- 新建子任务和后续创作会读取届时已保存的规划。
- 老任务继续使用原有上下文，不在重启或继续时强行套用新规划。

### 子任务上下文补齐

- 委派子任务继承原任务的显式参考文件，参考内容可出现在子任务的「资料与素材」中。
- 已交付任务继续创作也继承参考、审查模式、停止条件和时限，避免延续任务时丢失原有执行限制。
- 子任务仍从项目已合入版本开始，不把父任务正在修改的文件当成已交付成果。

### 执行边界

- 规划优先级不是完成百分比，也不意味着必须一次性实现全部系统。
- 功能包勾选不是已安装证明，不触发全量自动接入。
- 联机人数和服务器数量是设计目标，不声称已部署或已完成压测。
- 宣传草案不授权自动联系媒体、对外发布或付费投放。
- 任务目标与锁定的基础设定冲突时，提示 Codex 使用已有提问机制询问用户；这是执行约定，不是能证明模型永远遵守的硬性策略引擎。
