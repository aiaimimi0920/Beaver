## 记录问题并继续

1. AI 的一次补丁操作失败；测试发送“继续完成。如果刚才的操作失败，请重试并继续。”，
   API 返回 200，随后 Beaver 继续生成游戏。
2. Beaver 报告 PowerShell 写入 BOM 导致场景解析失败，随后自行修复并继续验证。
3. 达到 10 分钟预算后任务进入 `interrupted`；通过 API 发送
   “继续完成导出，并验证游戏可以启动。”后恢复，最终完成主任务。
4. `task.resourceText` 读取 `tests/export.log` 返回“资源不是有效 UTF-8 文本”，
   已记录读取能力缺口，改为读取可用的错误日志继续验证。
5. 导出错误日志存在退出清理错误：RID / ObjectDB 泄漏和资源仍在使用。
   AI 导出目录未通过 `game.verifyExport`，返回 409；标准 `game.export` 使用有效
   目标父目录后仍返回导出失败。核心导出服务遇到 `ERROR:` 会拒绝宣布交付成功，
   因此本轮不能宣布标准导出和包验证已经闭环。

导出未通过后，继续执行项目运行和任务认可，均返回 200；再通过 `task.followup`
提交短输入：“软件的导出操作失败了，日志里有资源退出清理错误。请修复并重新验证
Windows 导出。”后续任务 ID：`a373707f-1396-493d-8e67-bb66bde912cf`。
后续修复在本轮项目内完成，任务最终为 `completed`，认可接口返回 200。Beaver
报告关闭场景资源转换选项、补齐默认导出路径，直接导出和启动复验通过。
主测试代理随后重新调用标准 `game.export`，修复完成后及认可后均仍返回 409。
因此保留“标准导出接口仍失败”作为未解决问题；AI 的直接导出成功不能替代该接口的
验收结果。本轮已经执行恢复和复验，没有在首次失败处终止测试。

运行中的修复任务会启动同版本 `Beaver.exe --media-mcp` 辅助进程；该进程属于当前
任务的工具服务。最终复核时桌面实例仍为 PID 33808，媒体辅助进程为 PID 9180。
启动器关闭旧宿主后，会跳过已经随宿主退出的辅助进程，避免旧进程快照导致误报。
