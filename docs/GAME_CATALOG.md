# 游戏创作目录

## 当前规划目录与旧版执行方向

0.1.7 的新 UI 使用 64 类别、49 预设主题及自定义、3 评级、4 规模，并提供联机和三阶段规划，详见[项目规划交互契约](ui/PROJECT_BLUEPRINT.md)。新规划只保存 Beaver 数据库；创建时的功能勾选不再提交 AI 任务。

以下“创建方向”记录 **0.1.6 已有项目的 GameBrief 文件契约**，不是 0.1.7 新建界面的选项数量。它仍供已有项目的真实任务读取，不应删除或将新规划悄悄覆盖到该文件。后面的 10 个功能块目录仍有效。

## 0.1.6 创建方向（已有项目继续支持）

| 项目 | 0.1.6 选项 |
| --- | --- |
| 类型，可选主/副组合 | 叙事/视觉小说、角色扮演、探索冒险、生活模拟、经营管理、策略、解谜、生存制作、动作、平台跳跃、Roguelite、卡牌 |
| 题材 | 赛博朋克、太空探索、奇幻、现代都市、历史、废土末日、侦探悬疑、怪谈惊悚、校园青春、治愈日常、航海、自然生态 |
| 表现 | 像素 2D、手绘 2D、简约 2D、低多边形 3D、风格化 3D、文字为主 |
| 规模 | 可玩原型、精做一章、短篇游戏 |

规模对应的体验时长只是传给 Codex 的控制目标，不承诺生成耗时或已完成内容量。主副类型不重复。推荐是类型关联功能块的去重集合，并默认包含存档；用户仍自行决定是否接入，不因选择类型而自动消费 AI。

新建项目写入 UTF-8 `beaver.project.json`，包含 `schemaVersion: 1` 与 `design`。无此文件的已有 Godot 项目正常接管；未知版本或非法选项明确报错。再次接管刷新元数据，新任务从自己的文件快照读取方向，显式任务要求优先；任务中止续跑不悄悄替换目标。方向文件同其他项目文件一起参与差异合并和回退。

模板是初始工程骨架，目录是创作目标，功能块是待适配素材，三者不能混为一谈。当前夜航模板是 2D 对话调饮示例；选择 3D 风格不等于模板自动变成 3D 游戏。需要完全不同的游戏时可选空白骨架，并由 Codex 按目标创建。

## 功能块

0.1.8 新增的 **68 项引擎能力规划包**不包含源码，完整目录和来源键见[引擎能力功能包目录](ui/ENGINE_PACKAGES.md)。它们与以下 10 个源码包共同进入规划选择器，但不会进入真实接入、版本采用和更新流程。界面使用“功能包规划 / 源码包”两页区分，避免将计划误报成实现。

| 标识 | 名称 | 分类 | 当前基础 |
| --- | --- | --- | --- |
| dialogue | 数据驱动对话 | 叙事 | 原创 JSON 对话与接入规则，不是通用对话编辑器 |
| save-slot | 存档槽 | 基础能力 | 1.0.1 JSON 存档示例；本次补充读取错误和生产保存约束 |
| inventory | 物品与背包 | 玩法系统 | 数量增减、整批成本/奖励交换、快照恢复 |
| quests | 任务与目标 | 叙事 | 目标进度、完成判断、单次领奖、快照恢复 |
| relationship | 角色关系 | 叙事 | 关系数值限制、阶段查询、快照恢复 |
| economy | 货币与交易 | 玩法系统 | 虚拟货币余额、拒绝余额不足、快照恢复；非真实支付 |
| crafting | 配方与制作 | 玩法系统 | 配方定义与调用库存原子交换，避免失败后材料被部分消耗 |
| day-cycle | 时间与日程 | 玩法系统 | 显式时间推进、跨日、暂停、时段与快照；不擅自推进离线时间 |
| progression | 经验与等级 | 成长 | 多级经验结算、等级上限、恢复不重复发升级奖励 |
| localization | 多语言文本 | 基础能力 | 稳定文本 ID、参数、回退语言与原创示例；优先复用项目已有翻译机制 |

每个包包含 `feature.json`、源码或数据及 README 接入契约。Godot 模块独立于具体场景树，不强塞 UI；Codex 负责读取契约、连接项目状态/存档/输入/界面并验证。配方以库存的 `exchange` 方法为接入边界；项目已有同类系统时适配已有实现，不为凑目录重复造轮子。

更新继续使用已采用版本快照、新源文件和逐文件差异。AI 保留开发者定制并报告冲突；用户认可后才推进采用版本，完整标准回退恢复对应采用基线。分类并不等同于强制依赖自动安装。
