# 产品契约与首版范围

## 核心目的

Beaver 是专用的对话式游戏创作工作室，不是通用素材库加 AI 按钮，也不是暴露内部节点编排的工作流编辑器。素材管理参考 Billfish/Eagle 的审阅方式，但围绕游戏项目、任务和最终可玩的结果组织。

用户决定目标和质量，Codex 黑箱执行。制作中的 Godot/Blender 调用、脚本编写、模型生成与摆放等由 Codex 决定；应用只提供任务上下文、工具环境、输入输出、变更保护和结果审阅。应用直接提供的试玩和导出是交付入口，不是替 Codex 编排制作过程。

## 已确认的产品约束

1. 首个验收方向是参考《赛博朋克酒保行动》的类型，制作内容原创的对话调饮游戏，不复制其剧情、角色或素材。最终由用户判断是否满意。
2. 首版支持创建项目，也支持接管已有 Godot 项目。
3. 同项目可以多个任务并行；默认持续推进至目标结束，可以设置停止条件和时间限制。
4. 支持中止、补充要求、稍后继续，关闭界面不终止后台；托盘退出才结束应用，下次可继续。
5. 每个任务保留前后文件边界，支持确定性回退、保留指定文件和对话式回退。
6. 图片、多参考图片、问题区域、音频试听反馈、模型/场景/翻译和游戏截图均可成为任务上下文。
7. 游戏模板仅在创建时应用。功能块可后加；升级依据最后采用的官方版本、当前项目定制及最新官方内容，交给 AI 合并。
8. AI 服务两种来源：平台额度网关和用户自配 Base URL/Key。首版都优先在本机执行 Codex 与制作工具；未来高级会员才支持云执行。
9. 首要操作系统 Windows；macOS、Linux 在真实验收后扩展。
10. 首版“导出”是可运行玩家程序，不只是打包源项目。
11. 自有 itch 类游戏/素材集市、作者奖励、交易和外部渠道发行延期；未来包含 itch、Steam、Epic、微信小游戏。

## 当前迭代：先确认 UI 和语义

0.1.7 按用户最新要求先提供可编译、可交互的项目规划原型。类别、主题、目标评级、规模、在线容量，以及设计 / 开发 / 后期的 15 项投入和媒体 / 试玩 / 宣传草案，都需先由用户体验确认。新控件只保存规划、显示未来交付目标，不因点击空格子而实现或执行对应业务。三个阶段是表达创作重点，不是替 Codex 编排任务。详见[项目规划交互契约](ui/PROJECT_BLUEPRINT.md)。

已存在的真实任务能力不拆除，但新规划与其分离；明确进入原任务 / 功能块页面才能执行。此迭代不提前实现集市、真实渠道发布或服务器购买。

## 0.1.0 的实现解释

- 用户看任务目标、结果报告、素材和游戏；内部细节收在可展开事件记录中。
- `completed` 表示 Codex turn 结束且文件合入成功，**不代表用户认可艺术品质或玩法**。认可按钮单独记录。
- 非冲突文件合入与任务标准回退使用持久化日志。冲突保留工作副本，不用整项目覆盖解决。
- 中止和退出后采用显式“继续”，不自动重新花费 API 额度。
- 平台模式的客户端路由真实可用，但充值、账户、余额和结算后台尚未提供，界面不会虚构额度。
- 附带“夜航调饮室”是三位原创客人的可玩起步模板，不是已经由用户验收的完整商业游戏，也不是宣称由已配置真实模型自动生成的作品。
- 首批功能块为 JSON 存档和对话分支示例。新官方版本目前随应用资源更新；在线分发属于后续工作。

## 不应误读为首版已经完成的能力

完整素材集市、游戏商店、充值支付、多用户协作、云执行、微信小游戏导出适配、平台审核/发布、内嵌 Godot 场景编辑器、原生 `.blend` 实时预览、自动理解所有供应商的媒体协议、大规模资产索引优化和自动更新均不是本次交付声明。
