# Beaver UI 实现提示词

本文件供后续明确授权的 UI 设计或实现任务使用。提供这份文档不代表当前已经授权开发；需求讨论阶段只阅读、讨论或执行用户明确要求的文档工作。

## 可直接使用的提示词

> 你正在为 Beaver 设计或实现 UI。先完整读取本目录的 `README.md` 和 `DESIGN_SYSTEM.md`，再读取 `references/neuro/AI_PROMPT.md`、`references/neuro/DESIGN_SYSTEM.md`、`references/neuro/tokens.json`、`references/neuro/tokens.css`，并查看本地参考页或截图。不要依赖原作者机器上的绝对路径或全局 skill。
>
> 使用 Neuro 当前统一视觉基线：近黑不透明壳层、有限白色重点阅读面、信号黄 `#d9ff38`、信号绿 `#22c55e`、信息蓝 `#06b6d4`、危险红 `#f43f5e`。精确中性色和派生公式以上述令牌文件为源，不新造竞争主色。保留 Beaver 名称，不复制 Neuro / Loom 标志。
>
> 用户是任务的发起者和验收者，Codex 是自主执行的黑箱。UI 帮助表达目标、选择参考、审阅素材和游戏、控制并发任务及回退，不要求人类编辑 Codex 的工作流节点或审批每个内部步骤。
>
> 首版面向本地项目创作，可接管已有 Godot 项目；常规关闭窗口后任务继续在托盘后台执行，托盘退出才停止后台执行，任务可在下次继续。AI 接入同时支持平台额度和用户自配 API，服务来源与任务执行位置必须分开表达。
>
> 标准回退只执行确定的恢复，保留其他任务成果和指定文件；交叠冲突明确提示，不猜测覆盖。对话回退用于需要理解意图的恢复。不要把“AI 执行完成”写成“用户已认可”，不要把“导出工程文件”写成“获得可直接运行的游戏”。
>
> 参考页和 Loom 历史文档中的商店、设备、Art、Hook 协议、工作流图和演示数据不是 Beaver 已有能力。首版不实现自有集市、外部渠道发行或云端任务执行。历史玻璃/渐变风格不得覆盖当前设计基线。
>
> 实现前检查目标仓库真实存在的主题、共享组件、页面状态和宿主约束。仓库为空时不得引用虚构组件或顺便决定技术栈。按语义复用令牌，不做相似色全局替换，也不直接把文档参考页当产品页面。
>
> 保留默认、悬浮、焦点、禁用、加载、空态、错误和成功状态。支持键盘、Escape、焦点恢复、明确内部滚动、长文本和 reduced motion。不要为截图伪造运行结果或暴露密钥。
>
> 完成后报告实际变更和验证证据。参考页或上游历史测试通过不等于 Beaver 通过；真实 UI 必须在 Beaver 中验证。本次任务若仅为文档工作，就只验证文档，不伪造产品构建或发布。

## 使用时补充的任务上下文

- 当前是否仅讨论/整理文档，或已明确授权设计/开发。
- 本次目标页面、用户主任务、真实输入和产物。
- 允许修改的范围、需要保留的业务行为和已有未提交改动。
- 已确定的技术栈、真实主题入口和共享组件；未确定时明确说明未确定。
- 本次验证范围与仍未实现的能力。
