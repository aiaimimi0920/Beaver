# 给 AI 的 Neuro UI 实现提示词

下面这段提示词用于让任何 AI 在 Neuro 的其他程序中复用同一套设计。使用时，把目标仓库、目标页面和业务要求补充到提示词末尾。

如果当前环境提供 `$neuro-ui-style` skill，应先显式启用该 skill；skill 负责定位和执行流程，本文件夹负责精确设计内容。若环境不支持 skill，直接使用下面的完整提示词即可。

## 可直接使用的提示词

> 你正在为 Neuro 系列应用实现或调整 UI。首先完整读取本目录中的 `README.md`、`DESIGN_SYSTEM.md`、`tokens.json` 和 `tokens.css`，并打开 `index.html` 或查看 `screenshots/` 建立视觉基线。随后读取目标项目的真实主题、共享组件、页面入口、状态模型和测试，不得仅根据截图猜业务或假定组件已经存在。
>
> 使用“Neuro 设计方案”作为唯一设计基线：深色近黑壳层、白色重点阅读/选中面、信号黄 `#d9ff38`、信号绿 `#22c55e`、信息蓝 `#06b6d4`、危险红 `#f43f5e`，以及本目录定义的中性色。黄、绿只能各有一个主色；悬浮、按下、弱背景和边框必须通过透明度或 `color-mix` 派生，不得再创建竞争主色。
>
> 信号黄只用于当前激活、键盘焦点、唯一主 CTA 和需要注意的状态；信号绿用于品牌、在线、成功和完成；蓝色用于链接、同步、设备与低风险信息；红色用于错误、删除、高风险权限与破坏性操作。不要只靠颜色表达状态，必须同时使用文字、图标、边框或结构差异。
>
> 先保证真实业务、信息层级、紧凑密度和交互完整，再加入切角三角、斜线、同心圆、刻度和网格等装饰。这些装饰只能作为低密度结构信号，不得遮挡文字、扩大布局或制造持续动画。避免通用紫粉玻璃、漂浮光球、巨大圆角、满屏 pill、等权卡片墙和无意义的多层容器。
>
> 不要把参考网页的 Loom/MCP 示例数据复制成目标产品数据。应把设计令牌映射到目标仓库现有主题 API，优先扩展共享 primitive，而不是为单页硬编码一套 CSS。保留键盘、焦点、Escape、加载、空、错误、禁用、窄屏、长文本、内部滚动和 `prefers-reduced-motion` 行为。
>
> 完成后验证：颜色值和角色映射正确；正文及控件对比度可辨；主操作唯一；选中、悬浮、禁用、成功、警告、错误状态可区分；没有破坏真实业务；运行目标仓库要求的类型检查、测试和可行的浏览器/桌面视觉验证。报告实际修改、验证结果和仍未迁移的差异。

## AI 执行顺序

1. **建立事实基线**：定位目标应用真实加载的主题文件、组件库和页面入口。
2. **建立语义映射**：把 `tokens.json` 的角色映射到目标项目变量；不要批量替换相似色值。
3. **梳理页面任务**：标出主任务、唯一主操作、次级操作、状态、空态、错误态和滚动边界。
4. **小步实现**：先 token 和共享 primitive，再页面骨架，最后是局部装饰和动效。
5. **核验所有状态**：深色背景、白色焦点面、hover、focus、disabled、success、warning、danger、loading。
6. **验证真实应用**：参考网页通过不等于产品通过；必须在目标应用中运行验证。

## 不允许的捷径

- 不得新造第二个黄色或绿色主色来“丰富层次”。
- 不得把 success 绿色当成所有按钮的默认强调色。
- 不得把 signal yellow 同时铺满导航、标题、多个按钮和装饰。
- 不得把白色焦点面变成全局白底企业后台。
- 不得为了截图伪造 provider、用户、设备、Art、MCP 或连接状态。
- 不得引用目标仓库里不存在的 token、class、组件或桌面能力。
- 不得为了统一视觉而删除真实业务字段、权限提示或错误反馈。
