# Neuro 设计系统

## 1. 设计目标

Neuro 是一组面向个人 AI 工作流、设备、工具和内容编排的应用。界面需要像高密度的个人操作中台：明确、迅速、可靠，并保留足够的工业信号感，而不是营销网站或通用 SaaS 后台。

本方案融合两类已验证方向：

- Loom 当前紧凑的深色应用框架；
- 公告终端中的白色重点信息面、切角三角、斜线和同心圆。

## 2. 唯一颜色基线

### 主色

| 角色 | 色值 | 语义 |
| --- | --- | --- |
| 信号黄 | `#d9ff38` | 当前激活、焦点、唯一主 CTA、待用户注意 |
| 信号绿 | `#22c55e` | Neuro/Loom 品牌、在线、成功、完成、正向状态 |

黄色和绿色各自只有一个主色。Hover、pressed、soft background、border 必须从主色派生，不得注册新的竞争黄色或绿色。

### 语义辅助色

| 角色 | 色值 | 语义 |
| --- | --- | --- |
| 信息蓝 | `#06b6d4` | 链接、同步、设备、技术信息、低风险权限 |
| 危险红 | `#f43f5e` | 错误、删除、高风险权限、破坏性动作 |

警告默认使用信号黄，但必须配合“警告”文字、图标或明确边框；不能只靠黄色表达。

### 中性色

| 角色 | 色值 |
| --- | --- |
| 主背景 | `#06080d` |
| 一级表面 | `#090c11` |
| 面板 | `#0e1218` |
| 侧栏 | `#070a0f` |
| 控件 | `#111720` |
| 控件悬浮 | `#18222c` |
| 正文 | `#f7f8ef` |
| 次级文本 | `#929a9f` |
| 分隔线 | `rgba(255, 255, 255, 0.12)` |
| 白色焦点面 | `#f3f5f1` |
| 焦点面正文 | `#20252b` |
| 焦点面次级文本 | `#656b72` |

精确派生公式见 `tokens.css` 和 `tokens.json`。

## 3. 色彩比例和角色边界

- 黑、白、灰应承担约 80% 以上的界面面积。
- 黄用于少量最高优先级信号，不应成为大面积背景常态。
- 绿主要承担品牌与正向状态，不能与主 CTA 争抢。
- 蓝、红只在业务语义需要时出现。
- 白色焦点面只用于选中卡、重点阅读区、当前操作面或短时聚焦区；不可把整个应用改成白底后台。

比例是检查工具，不是机械配方。应以主任务是否清晰为最终判断。

## 4. 构图语言

### 应用框架

- 左侧 rail 负责一级导航、目录、筛选和状态入口。
- 顶栏保持紧凑，承载窗口控制、少量全局操作和当前上下文。
- 主区优先使用连续 board 或高密度行，而不是等权卡片墙。
- 长列表、正文和表单使用边界明确的内部滚动；不要让局部展开导致外层重排。

### 视觉结构

- 近不透明深色 slab 是默认表面；不用通用 glassmorphism。
- 使用细分隔线、窄圆角、局部切角、编号、kicker、刻度和网格建立层级。
- 信号三角用于标题区或关键阶段的方向提示。
- 斜线用于连接区域、进程方向或视觉切分。
- 同心圆用于连接、广播、设备或系统信号的背景隐喻。
- 三类结构图形保持低对比、低密度，不能遮挡内容或成为背景噪声。

### 白色焦点面

- 白底配灰黑文字，形成当前选中或重点阅读区域。
- 用信号黄细条、边线或角标连接深色壳层与白色内容。
- 白色焦点面内部必须改用 `focusInk` / `focusMuted`，不能继续沿用深色面上的白字。

## 5. 控件规范

### 按钮

- 每个操作上下文只保留一个黄色主按钮。
- 普通操作使用深色控件和细边框。
- 正向完成动作可用绿色边框或绿色次级按钮；除非它就是唯一最终动作，否则不升为主按钮。
- 删除和不可逆操作使用红色，且应用内二次确认，不使用浏览器或 Tauri 原生确认框。
- Disabled 通过明度、边框和交互状态共同表达，不能只把文字变灰到不可读。

### 输入与选择

- 文本、数字、下拉、密钥、滑杆和开关在常态下也要可辨，不依赖 hover 才能识别类型。
- Focus 使用信号黄 outline，并保持至少 2px 可见边界。
- 密钥和代码使用等宽字体，但标签与说明保持普通字体。
- 深色/白色焦点面上的 input 必须分别映射正确的文字和 placeholder 颜色。

### 状态与通知

- 信息、警告、错误、成功分别使用蓝、黄、红、绿，并同时提供文字或图标。
- 通知使用垂直堆叠；新通知排在下方，前项消失后自动上移；允许点击关闭；不得遮挡顶栏窗口按钮。
- Error 不因自动消失而失去可追踪性；需要长期处理的错误应同时保留在对应页面状态中。

### 卡片与行

- 能用一行表达的内容不扩成多层卡片。
- 卡片尺寸、描述行数和底部动作对齐保持稳定。
- 选中项可以使用白色焦点面或黄色左边信号条；未选中项不得持续高光。

## 6. 排版和密度

- 中文标题使用清晰的字重与层级，不机械套用全大写或超宽字距。
- 英文 micro-label 可以 uppercase、使用等宽字体或增加字距。
- 正文、次级说明、数字、状态不能只靠颜色区分。
- 删除“不言自明”的重复标签，但不得删除业务必要字段、权限、错误和结果语义。
- UI 高度和留白围绕任务密度确定；避免为了“高级感”堆叠空白和容器。

## 7. 交互与动效

- Hover 主要改变边框、表面明度和小幅位移，不使用大面积 glow。
- 展开/收缩应稳定网格和宽度，避免滚动条出现/消失或文本换行引起抖动。
- 动效服务于空间关系、状态变化和完成反馈，通常控制在 120-220ms。
- 支持键盘、可见焦点、合理 tab 顺序、Escape、焦点恢复和背景滚动锁定。
- 尊重 `prefers-reduced-motion`。

## 8. 页面原型

| 页面 | 推荐结构 |
| --- | --- |
| 设置 / 详情 / 编辑 | 左 rail + 右连续主板 + 可收缩分组 |
| 商店 / 注册表 | 紧凑工具栏 + 稳定卡片网格或高密度列表 + 分页 |
| 设备 / 服务管理 | 标题行 + 添加/批准动作 + 高密度设备条 + 编辑二级弹窗 |
| 工作流 / Hook 同步 | 工具栏与缩放同行 + 稳定画布 + 内部面板 |
| 运行状态 / 管理 | 高密度行 + 语义状态 + 只在需要时展示日志 |

## 9. 迁移规则

1. 先找目标仓库真实主题入口和共享组件。
2. 建立语义映射，不按相近色值做全局字符串替换。
3. 新共享组件优先使用目标项目当前命名规范；不要因为本目录示例使用 `--neuro-*` 就假设产品已有这些变量。
4. 局部修改不顺手重写全站；大规模迁移时再统一兼容层。
5. 参考网页中的 Loom、MCP、设备数据只是设计夹具，不代表功能已经接通。

## 10. 验收清单

- [ ] 唯一主 CTA 一眼可辨，没有多处黄色争抢。
- [ ] 黄、绿、蓝、红的角色没有互相替代。
- [ ] 白色焦点面使用深色文字，深色面使用浅色文字。
- [ ] 正文和控件在默认、hover、focus、disabled 状态均可读。
- [ ] 状态同时有颜色以外的可辨信息。
- [ ] 没有无意义的容器套容器、等权卡片墙或全局玻璃化。
- [ ] 长列表、弹窗、折叠区域和窄屏不会破坏外层布局。
- [ ] 键盘、Escape、焦点恢复、加载、错误、空态和 reduced motion 已验证。
- [ ] 目标项目真实测试和视觉检查通过，而不只是本参考页通过。
