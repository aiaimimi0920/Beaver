# Beaver UI 设计规范

状态：Beaver 的视觉基线与业务语义映射；正式图标已于 2026-09-06 确认，具体页面遵守紧凑界面约束。

本规范采用 [Neuro 完整设计系统](./references/neuro/DESIGN_SYSTEM.md)。精确颜色和状态派生以 [tokens.json](./references/neuro/tokens.json) 与 [tokens.css](./references/neuro/tokens.css) 为源，不另建竞争色板。

## 1. 产品边界

Beaver 是以 Godot 游戏项目为中心的本地对话创作应用。用户发出目标，Codex 自行拆分、调用工具和完成制作；用户查看素材、试玩、反馈并导出可运行的游戏。

- 首版支持新建及接管已有项目、素材审阅、并发任务、反馈、回退、环境准备和游戏导出。
- UI 组织用户目标、参考和产物，不要求用户操作节点图或审批 Codex 的每个制作步骤。
- 用户无需进入 Godot / Blender 编辑器。可视化选取与标注是需求输入，不是重建专业编辑器。
- 自有集市、外部渠道发行和云端任务执行属于未来范围；不得从参考页照搬成首版已可用页面。
- 平台 AI 额度与自配 API 两种接入属于首版，实际任务执行仍在本机。不要把服务来源标签当成执行位置标签。

## 2. 视觉身份

采用深色工业工作台语言，保持明确、紧凑和可靠，避免营销首页或通用卡片后台。

- 近黑、不透明的表面承担主要界面面积；黑白灰承担约 80% 以上面积，比例用于检查而非机械配方。
- 白色焦点面仅用于选中项、重点阅读面或当前操作区域；不得扩成全局白底。
- 使用细分隔线、中小圆角、有限切角、编号和低对比网格组织信息。
- 三角、斜线、同心圆只作低密度结构信号，不遮挡文字、素材或试玩画面，不制造持续动画。
- 避免紫粉玻璃化、漂浮光球、大面积发光、巨大圆角、满屏 pill 和无意义容器嵌套。
- 保留 Beaver 产品名称，不直接使用 Neuro / Loom 标志；正式使用用户选定的[「一句成游」图标](./BRANDING.md)，不再使用临时字母 B 标记。
- 测试游戏的美术风格属于游戏内容，不自动改变 Beaver 应用壳层的设计基线。

## 3. 颜色语义

| 角色 | 唯一基色 | Beaver 中的含义 |
| --- | --- | --- |
| 信号黄 | `#d9ff38` | 当前激活、键盘焦点、当前上下文唯一主操作、需要注意但非错误的情况 |
| 信号绿 | `#22c55e` | 品牌、真实在线状态、执行成功、完成和正向次级状态 |
| 信息蓝 | `#06b6d4` | 链接、技术信息、同步和低风险信息 |
| 危险红 | `#f43f5e` | 错误、删除、破坏性操作及高风险提示 |

| 中性角色 | 色值 |
| --- | --- |
| 主背景 / 一级表面 | `#06080d` / `#090c11` |
| 面板 / 侧栏 | `#0e1218` / `#070a0f` |
| 控件 / 控件悬浮 | `#111720` / `#18222c` |
| 正文 / 次级文本 | `#f7f8ef` / `#929a9f` |
| 分隔线 | `rgba(255, 255, 255, 0.12)` |
| 白色焦点面 | `#f3f5f1` |
| 焦点面正文 / 次级文本 | `#20252b` / `#656b72` |

- Hover、pressed、soft、border 从上述基色按上游公式派生，不新增第二种黄色或绿色主色。
- 每个操作上下文只有一个明显主操作；并发任务列表不能让所有任务按钮同时争抢黄色主 CTA。
- 绿色的“执行完成”不能被文案偷换成“用户已认可”。用户验收与 AI 报告完成需要明确区分。
- 状态必须同时使用文字、图标、边框或结构表达，不能只靠色差。
- 白色焦点面使用深色正文与输入文字，深色表面使用浅色文字。
- 不给原始图片、视频帧、模型材质或试玩内容施加品牌色滤镜。选中和标注样式属于界面覆盖层，不能伪装成已修改素材。

## 4. 构图、排版与密度

- 继承左侧导航/上下文入口、紧凑顶栏、连续主工作区的构图原则；本次不冻结具体页面布局或面板数量。
- 长列表、对话、属性与日志明确各自滚动边界，局部展开不推动整个窗口反复重排。
- 能用一行表达的信息不拆成多层卡片；素材缩略图可使用稳定网格，不机械套成等权指标卡墙。
- 控件、素材标题、描述行数和动作位置保持稳定，防止选择或异步更新造成跳动。
- 中文界面使用清楚的标题与短操作文案，不照搬英文全大写和超宽字距。
- 路径、代码、模型标识等技术值可使用等宽字体；协议标识不为汉化而改写。
- 删除重复说明，但不能删掉错误原因、停止条件、保存范围和结果语义。
- 详细日志和 Codex 工作汇报按需展开，不能挤占用户审阅素材和游戏的主要空间。

## 5. 首版业务映射

| 场景 | UI 应表达的内容 | 不应暗示的能力 |
| --- | --- | --- |
| 环境准备 | 检测结果、缺失工具、安装动作、实际可用状态 | 未验证即显示可用，或改写用户个人 Codex 配置 |
| 项目与模板 | 新建/接管项目、初始模板、功能块来源与版本 | 对已有项目强行重套模板 |
| 素材审阅 | 多选、参考关系、问题区域、音频反馈、截图和对象上下文 | 为套设计稿伪造素材或连接状态 |
| 任务 | 用户目标、停止条件、补充要求、执行状态和产物 | 要求人类编排 Codex 内部步骤 |
| 功能块更新 | 已采用基准、上游变化、合并结果或问题 | 下载新版即算合并成功 |
| 回退 | 目标任务、保留文件、冲突、标准/对话型回退的区别 | 标准回退会自动猜测跨任务冲突 |
| 试玩与导出 | 真实运行结果、目标系统、产物位置和失败信息 | 只有工程文件却标为可直接运行成品 |
| AI 接入 | 平台额度/自配 API、必要连接状态和配置 | 云端 AI 请求等同于云端运行 Codex |

## 6. 任务、后台与回退反馈

- 支持同时查看同一项目多个任务，各任务目标、进展、汇报和结果能够区分。
- 中止、补充要求、稍后继续和恢复任务的入口应清楚，不能只藏在终端输出中。
- 默认自主执行；视觉规范中的危险确认针对用户直接触发的破坏性操作，不扩展成 Codex 每个子步骤的重复审批。
- 常规关闭窗口表示转入托盘继续执行；托盘“退出程序”表示结束后台执行并保留后续继续所需状态。两者文案不能混用。
- 回退目标是撤销目标任务变化、保留其他任务成果与指定文件；冲突时明确阻止不确定覆盖并提供对话处理入口。
- 错误不能只出现在会消失的 toast 中，应能从对应任务或页面重新查看。
- 等待、暂停、中止、失败、执行完成和用户认可不能用同一个模糊的“完成”或同一图标代替。

## 7. 控件与交互

- 默认、hover、focus、disabled、loading、empty、success、warning、error 均需可辨。
- 输入框和选择控件不依赖 hover 才能看清，焦点至少保留 2px 可见边界。
- 密钥输入默认遮蔽，不把真实凭据放入设计稿、日志、截图或提示词示例。
- 破坏性操作使用红色语义和应用内确认，不以浏览器原生确认框代替设计规范。
- 弹窗支持 Escape、合理焦点进入与恢复、键盘导航和背景滚动锁定。
- 通知垂直堆叠、可关闭，不遮挡窗口控制；长期问题同时保留在所属界面。
- 动效用于解释状态或空间变化，通常为 120-220ms；遵守 `prefers-reduced-motion`。
- 展开、收缩、文本换行及滚动条出现不应引起明显宽度抖动。
- Windows 是首版必须验证的平台；macOS / Linux 的可用状态不得由参考页渲染成功推断。

## 8. Loom 经验的采用边界

参考 [Phase 27 UI 审计](./references/loom/analysis/phase-27-workflow-graph-ui-audit.md)、[Phase 27 阶段记录](./references/loom/progress/phase-27-workflow-graph-ui.md)与 [Phase 35 中文 UI 记录](./references/loom/progress/phase-35-cn-ui-hook-sync.md)：

- 采用清楚的选中反馈、内容与属性的对应关系、紧凑操作和中文短文案。
- 采用“把截图/选中内容作为后续操作上下文”的交互思想，不继承 Hook 专属协议。
- 不继承工作流节点图、YAML 编辑、Art 注册表或 Loom 商店作为 Beaver 的功能承诺。
- 不继承旧玻璃/渐变视觉。它与当前基线冲突时，以 Neuro 当前设计系统为准。
- 历史测试、截图和发布记录只描述上游，不证明 Beaver 已经完成实现。
