# Beaver 媒体功能为什么曾经有一个单独的 EXE

## 它做什么

beaver-media 是 Beaver 提供给任务会话的媒体工具适配器，不是另外一个游戏编辑器，也不是本地运行的图片或音乐生成模型。

它向会话暴露四个工具：

| 工具 | 用途 |
| --- | --- |
| generate_image | 根据提示词及参考素材请求图片生成接口，并把结果保存到任务工作目录 |
| generate_speech | 请求语音生成接口，并保存音频 |
| generate_music | 请求音乐生成接口，并保存音频 |
| translate_text | 请求文本模型完成翻译，将结果返回会话，由会话决定如何使用或归档 |

这层适配器负责使用 Beaver 为当前任务准备的服务地址、模型和凭据，处理返回结果、限制输出路径、避免覆盖冲突，并把成功或失败返回给任务会话。它不替用户决定游戏应该怎么做，也不接管 Codex 对任务的拆分和工具选择。

因此职责划分仍然是：用户提出目标，Codex 自行决定何时调用媒体工具；Beaver 提供统一的服务配置、项目边界和落盘规则。这里的“本地模式”指用户自行配置 API 服务，不意味着这个小程序内置了本地大模型。

## 能不能合进主程序

**可以，而且已经完成本次合并。之前的第二个 EXE 是独立的 MCP 启动入口，不是不可合并的技术要求。**

目前只需要同一个 Beaver.exe：

- 正常启动：进入桌面应用。
- 以 --media-mcp 启动：只进入无界面的媒体 MCP 模式，通过标准输入和标准输出交换消息。

无界面入口在 Tauri、WebView、数据库和单实例逻辑之前分流，不会打开第二个界面，也不创建桌面数据目录。任务的独立配置现在指向当前 Beaver.exe，并附带 --media-mcp。

这不是“把第二个 EXE 塞进资源，启动后再解压出来”。已经删除独立媒体 binary 的源入口，主程序直接调用同一个 Rust 库里的媒体服务实现；正常构建只生成主应用 binary。

## 单文件不等于单进程

执行任务时仍可以看到额外的 Beaver.exe 进程：那是任务会话按需启动的无界面工具进程，不是第二份安装文件，也不是隐藏的 Electron 或 Node 后台。

保留这种进程隔离有实际作用：每个任务有自己的项目目录与服务配置；工具的标准输入输出不会与桌面界面混在一起；会话关闭输入时，工具可以取消尚未完成的请求并退出。没有必要为了让进程列表只剩一行，再引入跨任务共享的本地 HTTP 服务和额外的生命周期管理。

## 本次验证结果

Release 主程序为 **11,281,920 字节，约 11.28 MB**。与之前主程序加媒体程序合计的 12,614,144 字节相比，减少了 1,332,224 字节。

验证专门把新的主程序复制到一个全新目录，目录里只有 Beaver.exe，没有 beaver-media.exe：

- 媒体协议与功能检查 16 项通过，包括生成接口、翻译、错误处理、路径限制、并发输出冲突及 EOF 退出。
- 无界面运行后，该目录仍只有一个 EXE，指定的桌面数据目录和 WebView 数据目录均未生成。
- 从这份孤立的 EXE 启动桌面，48 项桌面回归通过、0 页面错误；同时检查任务实际生成的 MCP command 正是这份 EXE，参数为 --media-mcp。
- 同一份 EXE 的窗口及单实例检查 5 项通过、0 页面错误。
- Rust 测试 70 项通过，TypeScript 类型检查及相关格式检查通过。

证据：

- output/validation/native-media-1788840198252/proof.json
- output/validation/native-shell-1788840233471/proof.json
- output/validation/native-window-1788840247454/proof.json
- output/validation/native-release-20260908-r3/proof.json

旧构建目录里可能仍保留历史 beaver-media.exe，它不是当前版本的依赖，也不应再加入新发布包。旧发布目录未覆盖，保留既有回退边界。

## 尚未等同于全部开发完成

此次解决的是“为什么有第二个媒体程序，以及能否合并”的结构问题。单文件应用不等于整个创作环境只有 11.28 MB：桌面界面仍使用系统 WebView2，游戏创作仍需要用户安装的 Godot、Blender、Codex 等外部工具。

完整发布包的许可证与依赖策略、旧数据迁移、真实模型创作和全新系统安装等验收仍按 NATIVE-MIGRATION.md 继续推进；不能以此次合并完成替代全部产品目标完成。
