## 对此前理解的修正

明白。我此前把 AI 参与限定在语义理解、创作和少数修正步骤，把其余调度都解释成必须由预先写好的程序决定，这个理解过窄。撤回“常规流程不增加 AI 调度调用”“只有特定环节才允许 AI”等限制。

你的要求是：任何环节都允许 AI 参与。理解目标、拆分任务、选择和组合工作流、决定参数、判断结果、处理问题以及决定下一步，都可以交给 Codex。用户仍可通过选项、自定义回答和审批表达自己的决定，询问频率沿用全局与单任务自动强度设置。

Beaver 提供可复用的标准化能力，让 Codex 能借助成熟流程完成任务。标准化的重点在于产物规格、工具衔接、工程集成和可检查的结果；AI 可以参与工作流内部的步骤与判断。

## 产品主程序与智能决策的关系

Beaver 是面向用户的独立产品和运行宿主，负责项目、对话、任务、素材浏览、预览、功能包、执行状态及交付记录，并在内部管理 Codex 的会话、上下文和工具入口。Codex 承担智能决策，通过 Beaver 暴露的工作流和业务接口操作项目。

两种关系可以同时成立：运行时，Beaver 启动和管理 Codex；任务推进时，Codex 决定调用 Beaver 的哪些能力。程序接收调用、执行相应能力并返回结果，Codex 再据此决定后续操作。Beaver 持续保存状态，并把这些过程呈现为用户能够理解和操作的产品体验。

因此无需把整个创作过程预先写成一条固定流水线，也无需规定每个步骤都必须调用 AI。Codex 可以选择确定性的工具步骤，也可以选择包含 AI 的工作流。程序负责准确执行接口约定、保存事实和返回结果；需要推理的实际决策交给 Codex。

## 标准化工作流提供什么

一个标准工作流应明确适用场景、输入参数、可执行步骤、产物规格以及结果检查方法。Codex 据此选择和调用，无需每次从零摸索完整的工具链、文件组织和引擎接入方法。

这些能力可以用 skill 提供使用说明与操作指引，用 MCP/API 提供实际调用入口。人类界面和其他 AI、程序也可以访问同一套业务能力。采用这些接口形式，不会改变 Beaver 作为产品主程序的定位。

工作流可以由确定性的程序步骤、AI 步骤或两者组合构成。需要固定执行的转换、导入和检查可以封装为程序能力；需要理解语义、选择方案或修复产物时，可以继续由 Codex 决策。具体职责根据实际工作流确定，不预先限制 AI 参与范围。

标准化也需要实际结果支持。工具执行失败、缺少必需文件或产物未通过约定检查时，应把具体结果返回 Codex，让其决定修复、重试、换方案或询问用户。程序不能仅凭一段完成声明把失败记成成功。对审美和创意等主观要求，允许 Codex 与用户评价。

这不要求每次生成相同内容，也不承诺每次尝试必然成功。目标是让成功交付的产物符合已声明的使用规格，使后续工程能够接续使用，并让未完成的部分有清楚的状态。

## 应用于 NPR 人物功能包

NPR 人物功能包应把插件、角色制作规范、可调用的接入能力和检查方法组合起来，作为 Beaver 管理的一项产品能力提供给 Codex 使用。

用户创建项目并启用该模块后，Beaver 应负责让插件与项目配置实际就绪，并向 Codex 提供相关工作流和规范。指定引擎目录为 `C:\Users\Public\nas_home\godot\export`，具体文件及兼容性仍需在实现阶段核验。

测试输入仍为“创建一个可爱的二次元女性角色，最好带上草帽”。Codex 理解目标，选择 NPR 相关工作流，决定制作方案并通过 Blender MCP 等能力推进建模。工作流帮助它完成符合规范的模型交付、材质与角色定义装配、引擎接入和结果检查。过程中出现问题，Codex 可以持续参与判断和修复。

用户在 Beaver 中查看对话、任务进度、角色素材和预览，并按自己的自动强度设置参与决策。实际验收仍通过 Beaver API 发起，测试操作者不直接调用 Blender、Godot 或 Codex 来代替产品完成任务；小问题记录后采用正常恢复继续推进。

验收应证明 Codex 能发现并实际使用 Beaver 提供的能力，工作流能帮助产出符合 NPR 使用规格的资产，执行和修复结果能回到 Beaver 的任务与素材界面中。无需把“减少 AI 调用”或“固定流程里没有 AI”作为验收目标。

## 商业目的与产品边界

你明确把销售 Beaver 这款软件作为首要商业目的。对外应交付完整、独立的 Beaver 产品，用户通过它完成目标、管理工程并使用素材。工作流、功能包和 Codex 集成共同服务于这个产品。

内部通过 skill、MCP 或 API 让 Codex 使用能力，是实现方式；对外的主要商品、使用入口和项目管理体验仍归属于 Beaver。可以继续向其他 AI 和程序开放接口，同时保持人类用户在 Beaver 内完成创作与管理的完整体验。

“Beaver 是上级程序”应有实际的产品职责支撑：它管理运行、项目状态、素材、工作流与交付。Codex 在其中承担智能决策，两者职责并存。软件价值落实在可用的工作流、稳定的工程接入、素材管理、可视化交互和完整交付体验上；这些内容属于后续需要实现和验证的范围。

本轮只修正文档中的理解，不实施举例中的 A 模块或绿色贴图功能，也不因商业目的额外加入尚未讨论的定价、授权或付费系统。
