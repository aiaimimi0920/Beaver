# Beaver 0.1.6 - 本机 API 与游戏创作目录

## 本机测试

- 当前开发机已按用户请求补齐正在使用的 API 地址、模型与 Key，覆盖原本空白的编程、审查和翻译配置。Windows 安全存储加密保存，未关闭旧版，也未改写个人 Codex 配置。
- 设置页新增“从本机 Codex 补齐”；显式操作，不是应用启动时偷偷导入，不覆盖另一个服务的设置。发布包没有个人 Key。
- 媒体能力不冒充文本能力：图像、语音和音乐需要相应模型与接口。

## 创建与功能块

- 主类型 + 可选副类型，12 种类型、12 种题材、6 种表现风格、3 种规模。方向保存进项目文件，真正进入任务上下文；再次接管读取最新方向，新任务读取自己的快照，旧任务继续时保留旧目标。
- 创建时可“加入推荐”或清空选择；功能块页可搜索、按分类筛选、只看适合此项目的项。保持紧凑表单，不新增解释型页面标题。
- 功能块由 2 个增加至 10 个。新增库存、目标进度、角色关系、虚拟货币、配方制作、游戏时间、等级成长和多语言文本，共 8 个 Godot 逻辑模块。
- 沿用现有 AI 接入与差异更新机制，不另造任务编排器。模板只能创建时应用，功能块后期仍可接入、审阅更新和回退。

分类与交互借鉴 [City Game Studio 官方介绍](https://www.city-game-studio.com/) 的类型、题材组合思路；具体目录和模块为 Beaver 自行编写，没有复制游戏资源、源代码或公司经营模拟系统。详见 [完整目录与边界](GAME_CATALOG.md)。

## 验证与限制

- `npm run check`：类型检查、35 个 Node 测试和构建通过。
- `gdscript-post-check --format`：8 个新增模块及 Godot 测试脚本，格式和 lint 通过。
- `npm run verify:features`：Godot 4.0.2 / 4.4.1 实际加载并执行新增模块，包括原子配方交换、重复领奖保护、存档恢复与本地化回退。
- 桌面验收覆盖创建组合、推荐、分类、搜索、项目文件、任务方向、静态 Key 导入不外泄，以及旧版侧栏固定位置、托盘、设置和工具检测回归。发布包验收结果以新目录 `RELEASE.json` 的 `runtimeVerified` 为准，详细证据在 `output/validation/`。

仍然只有空白和夜航调饮室两个创建模板。类型不是 12 套已完成游戏；功能块是可供 AI 适配的源码/数据基础，不是勾选即完成的游戏 UI。真实项目中的十模块联合接入、整部游戏体验和媒体生成质量仍需按任务验收。本次不新增平台发行、商店、云执行或非 Windows 发布。
