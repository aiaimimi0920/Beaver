## 已接入

### 创作与主动提问

- 打开真实项目后，创作页直接连接真实任务，不再操作示例任务。
- 为新 Codex 会话注册 `beaver_ask_user`，同时接收原生 `item/tool/requestUserInput`。
- 由 Codex 判断是否缺少必须由用户确认的创作意图或知识；Beaver 不替它推断上下文，也不主动虚构用户决定。
- 每次允许 1–3 个问题；支持自由回答，收到带选项的问题时也可以直接选取选项。
- 问题在原任务内形成关联对话，显示“需要你补充”，任务列表提供“待补充”入口，不额外启动一个重复的 AI 任务。
- 先把问题存入本地数据库，再停止该任务的 Codex 进程。等待期间不会合入其工作副本；其他任务可以继续执行。
- 回答必须完整、非空，且对应当前问题。答案和继续要求持久化后，恢复工作副本与原会话，开始新的执行轮次。
- 不是在重启后向失效的 RPC 请求发送回答，也不会伪造一个用户答案来结束工具调用。
- 等待状态在退出与重启后保留；并发重复提交和稍后重放旧答案都被拒绝，不能因此中止已经恢复的任务。
- 密钥类问题不进入这条普通创作问答通道。未支持的授权、执行批准请求仍被拒绝，不自动批准。

### 资料

- 真实读取项目 Markdown 文件，支持查找、新建、编辑、保存、重新读取、标题大纲和 Ctrl/Cmd+S。
- 点击“交给 AI”将真实相对路径加入创作参考，由用户继续描述目标；未保存的新文件或草稿不能作为已落盘资料提交。
- 人工保存复用项目锁、内容快照和持久化写入日志，生成独立的“编辑资料”变更记录，可从创作页标准回退。
- 读取时返回原始内容的 SHA-256；保存时检查该版本。如果其他任务或编辑器修改了文件，拒绝覆盖，保留当前草稿。
- 草稿按项目缓存在本机，切换页面或重启应用后可以继续编辑。缓存失败会显式提示。
- 限制为项目内 Markdown，拒绝路径穿越、符号链接及内部运行目录；单文件最大 512,000 字节，写入 UTF-8 无 BOM。

### 素材与归档

- 真实项目的素材入口连接现有文件检索、预览、导入与参考提交流程，不再显示预览中的示例素材。
- 给 Codex 的任务提示包含按需归档约定：`docs/world`、`docs/characters`、`docs/mechanics`、`docs/art`、`docs/audio`、`docs/production`、`docs/decisions`。
- 已有项目应沿用有效分类，不为凑目录生成空文档。资料选择和检索仍由 Codex 决定。
- 用户确认的答案首先保存在任务数据库中；将其整理为 Markdown 是给 Codex 的执行要求，不冒充 Beaver 已经自动完成归档。

## 建议试用

1. 打开现有 Godot 项目，进入“资料”，新建 `docs/characters/主角.md`，填写设定并保存。
2. 点击“交给 AI”，在创作页描述要完成的游戏目标。
3. 当 Codex 认为缺少关键设定时，在“待补充”中回答，然后点击“提交并继续”。
4. 可以先退出整个应用，再打开：待回答问题仍应保留。
5. 资料保存后，在外部编辑器修改同一文件，再尝试保存旧草稿，应该看到拒绝覆盖的提示。
6. 在创作列表选择“编辑资料”记录，检查文件变更或执行标准回退。

## 尚未完成与已知边界

- 本轮没有宣称真实模型已经生成完整游戏，也没有重新执行完整 Godot、Blender、插件安装或游戏导出端到端验证。
- `RELEASE.json.runtimeVerified` 仍为 `false`：上述定向桌面验证不替代既有完整运行门禁。
- 资料页目前是真实 Markdown 源码编辑器与大纲，不是完整 Obsidian 功能集；完整双向链接、阅读渲染、图谱和实时外部文件监听尚未接入。
- 素材页复用现有真实实现，没有在本轮完成全部 Eagle 式交互。
- 手工资料保存当前复用完整任务快照和工作副本。大项目的空间占用与保存延迟需要后续优化，不能把当前实现称为低成本增量快照。
- 独立工作目录和合入版本检查不等于操作系统强沙箱。当前 Codex 执行权限边界没有在本轮收紧；不能承诺其进程绝对无法访问原项目。
- 原有冲突拒绝覆盖与对话回退/整合机制继续保留，本轮没有新增万能语义合并或自动验证所有合并结果。
- 动态工具属于 Codex 实验协议。已验证当前本机版本；旧版本兼容性仍需单独检查。升级前已经创建、未注册工具的旧会话不承诺自动获得新增工具，必要时创建新任务。
- 未打开项目时仍保留明确标注的交互预览，预览不会写入项目或执行任务。

协议依据：[OpenAI Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)。新线程可以注册动态工具，其定义随线程保存并在恢复时加载；本轮同时以本机生成的协议定义和真实进程测试核实集成。
